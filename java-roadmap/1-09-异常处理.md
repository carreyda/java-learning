## 1. 什么是异常

程序运行过程中发生的意外情况叫做**异常（Exception）**。比如：

```java
int[] arr = {1, 2, 3};
System.out.println(arr[5]);  // ArrayIndexOutOfBoundsException

String s = null;
System.out.println(s.length());  // NullPointerException

int result = 10 / 0;  // ArithmeticException

String str = "abc";
int num = Integer.parseInt(str);  // NumberFormatException
```

不处理异常，程序会**直接崩溃**并打印堆栈信息。异常处理机制让程序能优雅地应对这些意外，而不是直接挂掉。

## 2. 异常体系结构

```
Throwable
  ├── Error（严重错误，不应该捕获）
  │     ├── OutOfMemoryError     堆内存溢出
  │     ├── StackOverflowError   栈溢出（无限递归）
  │     └── ...
  │
  └── Exception（异常，程序可以处理）
        ├── RuntimeException（运行时异常，非受检异常）
        │     ├── NullPointerException        空指针
        │     ├── ArrayIndexOutOfBoundsException  数组越界
        │     ├── ClassCastException          类型转换失败
        │     ├── ArithmeticException         算术异常（如除以零）
        │     ├── NumberFormatException       数字格式错误
        │     ├── IllegalArgumentException    非法参数
        │     ├── IllegalStateException       非法状态
        │     └── ...
        │
        └── 非 RuntimeException（受检异常，必须处理）
              ├── IOException           IO 操作异常
              ├── SQLException          数据库操作异常
              ├── ParseException        解析异常
              ├── FileNotFoundException 文件未找到
              └── ...
```

### 受检异常 vs 非受检异常

| 类型                    | 代表                                               | 编译器要求                  | 来源         |
| ----------------------- | -------------------------------------------------- | --------------------------- | ------------ |
| 受检异常（Checked）     | `IOException`、`SQLException`                      | 必须处理（catch 或 throws） | 外部资源操作 |
| 非受检异常（Unchecked） | `NullPointerException`、`IllegalArgumentException` | 不强制处理                  | 编程错误     |
| Error                   | `OutOfMemoryError`                                 | 不应捕获                    | JVM 级别错误 |

> **原则：** 受检异常代表"可预见的外部错误"（文件不存在、网络中断），必须显式处理。非受检异常代表"编程 bug"，应该修复代码而不是捕获。

## 3. try-catch-finally

### 3.1 基本语法

```java
try {
    // 可能抛出异常的代码
    int result = 10 / 0;
    System.out.println(result);  // 这行不会执行
} catch (ArithmeticException e) {
    // 捕获并处理异常
    System.out.println("捕获到异常：" + e.getMessage());  // / by zero
} finally {
    // 无论是否发生异常，都会执行
    System.out.println("finally 块执行了");
}
```

### 3.2 异常对象的常用方法

```java
try {
    int[] arr = new int[3];
    arr[10] = 1;
} catch (ArrayIndexOutOfBoundsException e) {
    e.getMessage();   // "Index 10 out of bounds for length 3"
    e.toString();     // "java.lang.ArrayIndexOutOfBoundsException: ..."
    e.printStackTrace(); // 打印完整堆栈信息（调试时用）
}
```

### 3.3 捕获多个异常

```java
// 方式一：多个 catch 块（从具体到抽象）
try {
    String s = null;
    int[] arr = new int[3];

    s.length();   // 可能 NullPointerException
    arr[10] = 1;  // 可能 ArrayIndexOutOfBoundsException
} catch (NullPointerException e) {
    System.out.println("空指针：" + e.getMessage());
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("数组越界：" + e.getMessage());
} catch (Exception e) {
    // 兜底：捕获其他所有异常
    System.out.println("其他异常：" + e.getMessage());
}

// 方式二：多异常合并（JDK 7+，异常类型用 | 分隔）
try {
    // ...
} catch (NullPointerException | ArrayIndexOutOfBoundsException e) {
    System.out.println("捕获到：" + e.getMessage());
}
```

> ⚠️ **catch 顺序很重要**：子类异常必须放在父类异常前面。如果父类在前，子类 catch 永远不会执行，编译器会报错。

### 3.4 finally 的特点

```java
// finally 一定执行，即使有 return
public static int test() {
    try {
        return 1;
    } finally {
        System.out.println("finally 执行了");
        // return 2;  // ⚠️ 不要在 finally 里 return，会覆盖 try 的 return
    }
}
// 输出：finally 执行了
// 返回值：1

// finally 的典型用途：释放资源
Connection conn = null;
try {
    conn = getConnection();
    // 操作数据库...
} catch (SQLException e) {
    e.printStackTrace();
} finally {
    if (conn != null) {
        try {
            conn.close();  // 确保连接被关闭
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}
```

## 4. throws 与 throw

### 4.1 throw：手动抛出异常

```java
public static double divide(int a, int b) {
    if (b == 0) {
        throw new ArithmeticException("除数不能为零");  // 手动抛出
    }
    return (double) a / b;
}

public static void validateAge(int age) {
    if (age < 0 || age > 150) {
        throw new IllegalArgumentException("年龄不合法：" + age);
    }
}
```

### 4.2 throws：声明方法可能抛出的异常

```java
// 受检异常必须用 throws 声明，或者在方法内部处理
public static String readFile(String path) throws IOException {
    // 这里可能抛出 IOException
    BufferedReader reader = new BufferedReader(new FileReader(path));
    return reader.readLine();
}

// 调用方必须处理
public static void main(String[] args) {
    try {
        String content = readFile("test.txt");
    } catch (IOException e) {
        System.out.println("读取文件失败：" + e.getMessage());
    }
}
```

### 4.3 异常链（Exception Chaining）

把原始异常包装在新异常里，保留完整的错误上下文：

```java
public static void loadConfig(String path) throws RuntimeException {
    try {
        String content = readFile(path);
        // 解析配置...
    } catch (IOException e) {
        // 把 IOException 包装成业务异常，保留原始异常信息
        throw new RuntimeException("加载配置文件失败：" + path, e);
    }
}

// 调用方捕获时可以用 getCause() 获取原始异常
try {
    loadConfig("config.yml");
} catch (RuntimeException e) {
    System.out.println(e.getMessage());
    System.out.println("原始原因：" + e.getCause().getMessage());
}
```

## 5. 自定义异常

### 5.1 为什么需要自定义异常

Java 内置异常描述的是通用错误，业务开发中需要更具体的异常类型来区分不同的业务错误：

```java
// 不好的做法：用通用异常，调用方无法区分是什么业务错误
throw new RuntimeException("用户不存在");
throw new RuntimeException("余额不足");
throw new RuntimeException("权限不足");

// 好的做法：自定义异常，语义清晰
throw new UserNotFoundException("用户不存在：userId=" + userId);
throw new InsufficientBalanceException("余额不足，当前余额：" + balance);
throw new PermissionDeniedException("无权限访问该资源");
```

### 5.2 自定义运行时异常（最常用）

```java
// 继承 RuntimeException（不需要强制处理，适合业务异常）
public class UserNotFoundException extends RuntimeException {

    private final Long userId;

    public UserNotFoundException(Long userId) {
        super("用户不存在：userId=" + userId);
        this.userId = userId;
    }

    public UserNotFoundException(String message) {
        super(message);
        this.userId = null;
    }

    public UserNotFoundException(String message, Throwable cause) {
        super(message, cause);
        this.userId = null;
    }

    public Long getUserId() {
        return userId;
    }
}
```

```java
// 使用
public User findUser(Long userId) {
    User user = userRepository.findById(userId);
    if (user == null) {
        throw new UserNotFoundException(userId);
    }
    return user;
}
```

### 5.3 常见的业务异常设计模式

实际项目中通常定义一个业务异常基类：

```java
// 业务异常基类
public class BusinessException extends RuntimeException {

    private final int code;      // 错误码
    private final String message; // 错误信息

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
        this.message = message;
    }

    public BusinessException(int code, String message, Throwable cause) {
        super(message, cause);
        this.code = code;
        this.message = message;
    }

    public int getCode() { return code; }

    @Override
    public String getMessage() { return message; }
}

// 具体业务异常继承基类
public class UserNotFoundException extends BusinessException {
    public UserNotFoundException(Long userId) {
        super(404, "用户不存在：" + userId);
    }
}

public class InsufficientBalanceException extends BusinessException {
    public InsufficientBalanceException(double balance) {
        super(400, "余额不足，当前余额：" + balance);
    }
}

public class PermissionDeniedException extends BusinessException {
    public PermissionDeniedException() {
        super(403, "无权限访问该资源");
    }
}
```

## 6. try-with-resources

### 6.1 为什么需要 try-with-resources

传统 finally 关闭资源的写法很繁琐，而且嵌套的 try-finally 容易出错：

```java
// 传统写法：冗长且容易遗漏
BufferedReader reader = null;
try {
    reader = new BufferedReader(new FileReader("test.txt"));
    String line = reader.readLine();
    System.out.println(line);
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (reader != null) {
        try {
            reader.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### 6.2 try-with-resources 语法（JDK 7+）

资源声明在 `try(...)` 括号里，代码块执行完后**自动关闭**：

```java
// 简洁优雅
try (BufferedReader reader = new BufferedReader(new FileReader("test.txt"))) {
    String line = reader.readLine();
    System.out.println(line);
} catch (IOException e) {
    e.printStackTrace();
}
// reader.close() 自动调用，无需手动写 finally
```

### 6.3 同时管理多个资源

```java
// 多个资源用分号分隔，关闭顺序与声明顺序相反
try (
    FileInputStream fis = new FileInputStream("input.txt");
    FileOutputStream fos = new FileOutputStream("output.txt")
) {
    byte[] buffer = new byte[1024];
    int len;
    while ((len = fis.read(buffer)) != -1) {
        fos.write(buffer, 0, len);
    }
} catch (IOException e) {
    e.printStackTrace();
}
// 先关 fos，再关 fis
```

### 6.4 实现 AutoCloseable

自定义类也可以用 try-with-resources，只需实现 `AutoCloseable` 接口：

```java
public class DatabaseConnection implements AutoCloseable {

    private final String url;

    public DatabaseConnection(String url) {
        this.url = url;
        System.out.println("打开连接：" + url);
    }

    public void query(String sql) {
        System.out.println("执行查询：" + sql);
    }

    @Override
    public void close() {
        System.out.println("关闭连接：" + url);
    }
}

// 使用
try (DatabaseConnection conn = new DatabaseConnection("jdbc:mysql://localhost/db")) {
    conn.query("SELECT * FROM users");
}
// 输出：
// 打开连接：jdbc:mysql://localhost/db
// 执行查询：SELECT * FROM users
// 关闭连接：jdbc:mysql://localhost/db
```

## 7. 异常处理最佳实践

### 7.1 不要吞掉异常

```java
// ❌ 最糟糕的做法：捕获了但什么都不做，问题被掩盖
try {
    riskyOperation();
} catch (Exception e) {
    // 什么都不写
}

// ❌ 只打印，没有处理，调用方不知道出错了
try {
    riskyOperation();
} catch (Exception e) {
    e.printStackTrace();
}

// ✅ 至少记录日志，或者重新抛出
try {
    riskyOperation();
} catch (Exception e) {
    log.error("操作失败", e);
    throw new BusinessException(500, "操作失败", e);
}
```

### 7.2 不要捕获 Exception 或 Throwable（除非必要）

```java
// ❌ 太宽泛，连 NullPointerException 这种 bug 也被掩盖了
try {
    doSomething();
} catch (Exception e) {
    // 吃掉了所有异常
}

// ✅ 只捕获你预期的、能处理的具体异常
try {
    String content = readFile(path);
} catch (FileNotFoundException e) {
    // 文件不存在，用默认配置
    return defaultConfig();
} catch (IOException e) {
    // 读取失败，记录并抛出
    log.error("读取配置失败", e);
    throw new ConfigLoadException("读取配置失败", e);
}
```

### 7.3 在合适的层次处理异常

```java
// Repository 层：抛出，不处理
public User findById(Long id) throws SQLException {
    // 数据库操作，让上层决定如何处理
}

// Service 层：转换为业务异常
public User getUser(Long id) {
    try {
        User user = userRepository.findById(id);
        if (user == null) throw new UserNotFoundException(id);
        return user;
    } catch (SQLException e) {
        throw new BusinessException(500, "查询用户失败", e);
    }
}

// Controller 层：统一捕获，返回给客户端
// （Spring Boot 中用 @ExceptionHandler 或全局异常处理器）
```

### 7.4 异常信息要有意义

```java
// ❌ 信息不足，排查困难
throw new RuntimeException("操作失败");

// ✅ 包含关键上下文，便于排查
throw new UserNotFoundException(
    "用户不存在：userId=" + userId + ", 操作：" + operation
);
```

### 7.5 不要用异常做流程控制

```java
// ❌ 用异常做条件判断，性能差，可读性差
try {
    int index = list.indexOf(item);
    doSomething(index);
} catch (IndexOutOfBoundsException e) {
    // 说明不存在
}

// ✅ 用正常的条件判断
if (list.contains(item)) {
    int index = list.indexOf(item);
    doSomething(index);
}
```

## 8. 和 JavaScript 的对比

### 基本语法对比

```javascript
// JavaScript
try {
  JSON.parse("invalid json");
} catch (error) {
  console.log(error.message);
  console.log(error.name); // SyntaxError
} finally {
  console.log("finally");
}

// 抛出
throw new Error("出错了");
throw new TypeError("类型错误");
```

```java
// Java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println(e.getMessage());
    System.out.println(e.getClass().getName());
} finally {
    System.out.println("finally");
}

// 抛出
throw new RuntimeException("出错了");
throw new IllegalArgumentException("参数错误");
```

### 主要差异

| 特性               | Java                            | JavaScript                          |
| ------------------ | ------------------------------- | ----------------------------------- |
| 受检异常           | ✅ 编译器强制处理               | ❌ 无此概念                         |
| 多 catch 块        | ✅ 按类型分别处理               | ❌ 只有一个 catch，需要手动判断类型 |
| 异常类型           | 丰富的异常层次体系              | Error 和自定义 Error 子类           |
| try-with-resources | ✅ JDK 7+                       | ❌ 无原生支持（需手动 finally）     |
| finally            | ✅                              | ✅                                  |
| 自定义异常         | 继承 Exception/RuntimeException | 继承 Error 或直接 throw 对象        |

```javascript
// JS 只有一个 catch，类型判断靠手动
try {
  doSomething();
} catch (e) {
  if (e instanceof TypeError) {
    // 类型错误
  } else if (e instanceof RangeError) {
    // 范围错误
  } else {
    throw e; // 不认识的重新抛出
  }
}
```

```java
// Java 多 catch，类型由编译器保证
try {
    doSomething();
} catch (NullPointerException e) {
    // 空指针
} catch (IllegalArgumentException e) {
    // 参数错误
} catch (Exception e) {
    throw e;
}
```

## 常见问题

**Q：受检异常和非受检异常怎么选？自定义时用哪个？**  
A：实际项目中**几乎都用非受检异常**（继承 `RuntimeException`）。受检异常调用方必须处理，非常繁琐，Spring 等主流框架也是这样设计的。只有在"调用方必须明确处理，不处理会有严重后果"的场景才考虑受检异常（如文件操作、网络操作的底层 API）。

**Q：`finally` 里能 `return` 吗？**  
A：语法上可以，但**强烈不建议**。finally 里的 return 会覆盖 try 或 catch 里的 return，并且会吞掉异常（如果有的话），导致非常难以追踪的 bug。

**Q：`catch (Exception e)` 和 `catch (Throwable e)` 有什么区别？**  
A：`Throwable` 还包含 `Error`（如 `OutOfMemoryError`），通常不应该捕获 Error，因为 JVM 出现 Error 时程序往往已经无法恢复。除非是特定场景（如框架层需要捕获所有错误来打日志），否则用 `catch (Exception e)` 就够了。

**Q：`e.printStackTrace()` 和日志框架有什么区别？**  
A：`e.printStackTrace()` 输出到标准错误流，格式固定，无法控制日志级别，生产环境不推荐。日志框架（Logback/Log4j2）可以控制级别、输出格式、输出目标（文件、远程等），生产环境统一用日志框架。阶段四工程化那节会详细讲。

**Q：空指针异常（NPE）怎么避免？**  
A：几种常见方式：

```java
// 1. 提前判断 null
if (str != null && str.length() > 0) { ... }

// 2. 用 Optional 包装（1-14 会讲）
Optional.ofNullable(str).ifPresent(s -> System.out.println(s.length()));

// 3. 使用工具方法
Objects.requireNonNull(param, "param 不能为 null");

// 4. 字符串比较时，常量放前面
"expected".equals(variable);  // variable 为 null 也不会 NPE
```
