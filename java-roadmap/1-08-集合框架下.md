## 1. ArrayList 底层原理

### 1.1 底层数据结构

`ArrayList` 底层是一个 **Object 数组**：

```java
// ArrayList 源码简化版
public class ArrayList<E> {
    Object[] elementData;  // 底层数组
    int size;              // 实际元素个数（不是数组长度）

    // 默认初始容量
    private static final int DEFAULT_CAPACITY = 10;
}
```

### 1.2 扩容机制

```
初始容量：10（首次 add 时才分配）

触发扩容：size == elementData.length 时，即数组满了

扩容规则：新容量 = 旧容量 × 1.5
  10 → 15 → 22 → 33 → 49 → ...

扩容步骤：
  1. 创建一个新的更大数组
  2. 把旧数组的元素全部复制到新数组（Arrays.copyOf）
  3. 用新数组替换旧数组
```

```java
// 演示扩容影响性能的场景
List<Integer> list = new ArrayList<>();  // 初始容量 10

// 添加 10000 个元素，会触发多次扩容和数组复制
for (int i = 0; i < 10000; i++) {
    list.add(i);
}

// 如果提前知道大概数量，指定初始容量，避免频繁扩容
List<Integer> list2 = new ArrayList<>(10000);  // 直接分配 10000 的容量
for (int i = 0; i < 10000; i++) {
    list2.add(i);
}
```

### 1.3 时间复杂度

| 操作                    | 时间复杂度 | 说明                     |
| ----------------------- | ---------- | ------------------------ |
| `get(index)`            | O(1)       | 数组随机访问，直接按下标 |
| `add(e)`（尾部）        | O(1) 均摊  | 偶尔触发扩容是 O(n)      |
| `add(index, e)`（中间） | O(n)       | 需要移动后面所有元素     |
| `remove(index)`（中间） | O(n)       | 需要移动后面所有元素     |
| `contains(e)`           | O(n)       | 需要遍历查找             |

**结论：** ArrayList 适合随机访问、尾部增删；中间频繁插入删除性能差，应考虑 LinkedList。

### 1.4 LinkedList vs ArrayList 对比

| 操作                   | ArrayList        | LinkedList                 |
| ---------------------- | ---------------- | -------------------------- |
| 随机访问 `get(i)`      | O(1) ✅          | O(n) ❌                    |
| 尾部插入               | O(1) 均摊        | O(1)                       |
| 头部插入               | O(n) ❌          | O(1) ✅                    |
| 中间插入（已有迭代器） | O(n)             | O(1)                       |
| 内存占用               | 较小（连续数组） | 较大（每个节点存前后指针） |

> **实际建议：** 90% 的场景用 ArrayList 就够了。LinkedList 随机访问慢，内存占用也更多，只有明确需要频繁头部操作时再用。

## 2. HashMap 底层原理

### 2.1 整体结构

JDK 8 之后，HashMap 底层是 **数组 + 链表 + 红黑树** 的组合：

```
数组（哈希桶）
index: [0]  → null
       [1]  → Entry("李四", 85)
       [2]  → null
       [3]  → Entry("张三", 90) → Entry("赵六", 78)  ← 链表（哈希冲突）
       [4]  → null
       [5]  → Entry("王五", 92)
       ...
       [15] → null
```

### 2.2 put 的过程

```
map.put("张三", 90) 时发生了什么：

1. 计算 key 的 hashCode()："张三".hashCode() = 某个整数

2. 哈希扰动：对 hashCode 进行位运算，让分布更均匀
   hash = (h = key.hashCode()) ^ (h >>> 16)

3. 计算数组下标：index = hash & (数组长度 - 1)
   假设数组长度 16，index = hash & 15

4. 放入对应位置：
   - 该位置为空 → 直接放
   - 该位置有元素（哈希冲突）：
     - key 相同 → 覆盖旧值
     - key 不同 → 加入链表尾部

5. 检查链表长度：
   - 链表长度 ≥ 8 且数组长度 ≥ 64 → 链表转红黑树
   - 链表长度 < 8 → 保持链表

6. 检查是否需要扩容（见下一节）
```

### 2.3 扩容机制

```
默认初始容量：16
负载因子（loadFactor）：0.75

扩容触发：size > 容量 × loadFactor
  即：16 × 0.75 = 12，存入第 13 个元素时触发扩容

扩容规则：新容量 = 旧容量 × 2
  16 → 32 → 64 → 128 → ...

扩容时：所有元素重新计算下标（rehash），重新分配位置
  这是一个 O(n) 的操作，代价较高
```

```java
// 如果提前知道数据量，指定初始容量减少扩容
// 公式：initialCapacity = 预期元素数量 / 0.75 + 1
int expectedSize = 1000;
Map<String, Integer> map = new HashMap<>((int)(expectedSize / 0.75 + 1));
```

### 2.4 为什么链表长度 ≥ 8 转红黑树

- 链表查找是 O(n)，当链表很长时性能退化严重
- 红黑树查找是 O(log n)，链表长时性能更好
- 8 是统计上的经验值：正常哈希分布下，链表长度超过 8 的概率极低（约千万分之六），一旦超过说明哈希冲突严重，需要用树来优化

### 2.5 get 的过程

```
map.get("张三") 时：

1. 计算 "张三" 的 hash，找到数组下标
2. 该位置为空 → 返回 null
3. 该位置有元素：
   - 只有一个，且 key 相等 → 返回 value
   - 是红黑树 → 树查找，O(log n)
   - 是链表 → 遍历链表，逐个比较 key，O(n)
```

### 2.6 为什么重写 equals 必须同时重写 hashCode

```java
public class Student {
    private String name;
    private int age;

    // 只重写 equals，不重写 hashCode
    @Override
    public boolean equals(Object obj) {
        if (!(obj instanceof Student)) return false;
        Student other = (Student) obj;
        return this.name.equals(other.name) && this.age == other.age;
    }
    // 没有重写 hashCode！
}

Map<Student, String> map = new HashMap<>();
Student s1 = new Student("张三", 20);
map.put(s1, "北京");

Student s2 = new Student("张三", 20);  // 内容和 s1 相同
System.out.println(map.get(s2));  // null！！！

// 原因：
// s1 和 s2 的 equals() 返回 true（内容相同）
// 但 hashCode() 不同（用的是 Object 默认实现，基于内存地址）
// HashMap 先比 hashCode，不同就直接认为是不同的 key
// 所以找不到 s1 放进去的值
```

**规则：** 如果两个对象 `equals()` 为 true，它们的 `hashCode()` 必须相同。

## 3. 集合排序

### 3.1 基本类型排序

```java
List<Integer> nums = new ArrayList<>(List.of(5, 2, 8, 1, 9, 3));

// 升序（默认）
Collections.sort(nums);
System.out.println(nums);  // [1, 2, 3, 5, 8, 9]

// 降序
Collections.sort(nums, Collections.reverseOrder());
System.out.println(nums);  // [9, 8, 5, 3, 2, 1]

// JDK 8+ 用 List.sort()
nums.sort(null);  // 升序，null 表示用自然顺序
nums.sort(Collections.reverseOrder());  // 降序
```

### 3.2 字符串排序

```java
List<String> names = new ArrayList<>(List.of("张三", "李四", "王五", "赵六"));

// 按字母顺序（Unicode 码点）
Collections.sort(names);
System.out.println(names);

// 按字符串长度排序
names.sort((a, b) -> a.length() - b.length());

// 按长度降序
names.sort((a, b) -> b.length() - a.length());
```

## 4. Comparable 与 Comparator

### 4.1 Comparable：自然排序（内部比较器）

让类实现 `Comparable` 接口，定义该类对象的默认排序规则：

```java
public class Student implements Comparable<Student> {
    private String name;
    private int age;
    private double gpa;

    public Student(String name, int age, double gpa) {
        this.name = name;
        this.age = age;
        this.gpa = gpa;
    }

    // 定义自然排序：按 gpa 升序
    @Override
    public int compareTo(Student other) {
        // 返回负数：this 排在 other 前面
        // 返回 0：相等
        // 返回正数：this 排在 other 后面
        return Double.compare(this.gpa, other.gpa);
    }

    @Override
    public String toString() {
        return name + "(" + gpa + ")";
    }
}
```

```java
List<Student> students = new ArrayList<>();
students.add(new Student("张三", 20, 3.5));
students.add(new Student("李四", 21, 3.8));
students.add(new Student("王五", 19, 3.2));
students.add(new Student("赵六", 22, 3.9));

Collections.sort(students);  // 按 compareTo 定义的规则排序
System.out.println(students);
// [王五(3.2), 张三(3.5), 李四(3.8), 赵六(3.9)]
```

### 4.2 Comparator：定制排序（外部比较器）

不修改类本身，在排序时临时指定规则：

```java
List<Student> students = new ArrayList<>();
students.add(new Student("张三", 20, 3.5));
students.add(new Student("李四", 21, 3.8));
students.add(new Student("王五", 19, 3.2));
students.add(new Student("赵六", 22, 3.9));

// 按年龄升序
students.sort((s1, s2) -> s1.getAge() - s2.getAge());
System.out.println(students);

// 按 gpa 降序
students.sort((s1, s2) -> Double.compare(s2.getGpa(), s1.getGpa()));

// 用 Comparator 工厂方法（更推荐，可读性好）
students.sort(Comparator.comparing(Student::getGpa));           // 按 gpa 升序
students.sort(Comparator.comparing(Student::getGpa).reversed()); // 按 gpa 降序
students.sort(Comparator.comparing(Student::getName));           // 按名字字母序
```

### 4.3 多级排序

```java
// 先按 gpa 降序，gpa 相同再按年龄升序
students.sort(
    Comparator.comparing(Student::getGpa).reversed()
              .thenComparing(Student::getAge)
);
```

### 4.4 TreeSet / TreeMap 中使用 Comparator

```java
// TreeSet 默认用 Comparable 的自然排序
// 可以传入 Comparator 覆盖
Set<Student> set = new TreeSet<>(
    Comparator.comparing(Student::getGpa).reversed()
);
set.add(new Student("张三", 20, 3.5));
set.add(new Student("李四", 21, 3.8));
set.add(new Student("王五", 19, 3.2));

// 按 gpa 降序存储
set.forEach(System.out::println);
```

## 5. Collections 与 Arrays 补充

### 5.1 Collections 补充

```java
List<Integer> list = new ArrayList<>(List.of(3, 1, 4, 1, 5, 9, 2, 6));

// 二分查找（必须先排序）
Collections.sort(list);
int index = Collections.binarySearch(list, 5);  // 找到返回下标，找不到返回负数

// 交换两个位置的元素
Collections.swap(list, 0, list.size() - 1);

// 旋转（循环移位）
Collections.rotate(list, 2);  // 每个元素向右移动2位

// 复制（dest 必须和 src 一样长）
List<Integer> dest = new ArrayList<>(Collections.nCopies(list.size(), 0));
Collections.copy(dest, list);
```

### 5.2 Arrays 补充

```java
int[] arr = {5, 2, 8, 1, 9};

// 排序
Arrays.sort(arr);

// 并行排序（大数组更快，利用多核）
Arrays.parallelSort(arr);

// 流（Stream）操作
int sum = Arrays.stream(arr).sum();
int max = Arrays.stream(arr).max().getAsInt();
long count = Arrays.stream(arr).filter(x -> x > 3).count();

// 转 List
List<Integer> list = Arrays.stream(arr)
    .boxed()  // int → Integer
    .collect(java.util.stream.Collectors.toList());
```

## 7. 面试高频考点汇总

> 这一节把集合相关的面试题系统梳理一下，后续面试准备阶段会深入展开。

### ArrayList vs LinkedList

**Q：ArrayList 和 LinkedList 的区别？**

ArrayList 底层是数组，随机访问 O(1)，中间插删 O(n)，内存连续，CPU 缓存友好。LinkedList 底层是双向链表，头尾插删 O(1)，随机访问 O(n)，每个节点额外存两个指针，内存开销大。实际开发中 ArrayList 几乎是首选，LinkedList 使用场景很少。

### HashMap 相关

**Q：HashMap 的底层结构？**

JDK 8 之前：数组 + 链表。JDK 8 之后：数组 + 链表 + 红黑树。链表长度 ≥ 8 且数组容量 ≥ 64 时，链表转红黑树。

**Q：HashMap 的默认初始容量和负载因子？**

默认容量 16，负载因子 0.75，扩容阈值 = 容量 × 负载因子 = 12。

**Q：为什么 HashMap 的容量必须是 2 的幂次方？**

计算下标时用 `hash & (capacity - 1)` 代替取模 `hash % capacity`，位运算更快。2 的幂次方减 1 的二进制全是 1（如 15 = 1111），与运算结果能均匀分布在数组各位置。

**Q：HashMap 和 HashTable 的区别？**

HashTable 线程安全（方法加 `synchronized`），不允许 null key/value，性能差，已过时。HashMap 非线程安全，允许一个 null key 和多个 null value，性能好。线程安全场景用 `ConcurrentHashMap`。

**Q：HashMap 和 LinkedHashMap 的区别？**

LinkedHashMap 继承 HashMap，额外维护了一个双向链表记录插入顺序（或访问顺序），迭代顺序可预测。

### Set 相关

**Q：HashSet 的底层实现？**

HashSet 底层就是一个 `HashMap`，元素存在 HashMap 的 key 上，value 统一是一个固定的 `PRESENT` 对象占位。

**Q：HashSet、LinkedHashSet、TreeSet 怎么选？**

不需要顺序用 HashSet（最快）；需要保持插入顺序用 LinkedHashSet；需要自动排序用 TreeSet（元素要实现 Comparable 或传入 Comparator）。

### Comparable vs Comparator

**Q：Comparable 和 Comparator 的区别？**

`Comparable` 是类内部实现的接口（`compareTo`），定义该类的自然排序，改动类本身。`Comparator` 是外部传入的比较器，不修改原类，更灵活，可以定义多种不同的排序规则。

## 常见问题

**Q：HashMap 允许 null key 吗？**  
A：允许，且只能有一个 null key（hash 为 0，固定放在数组下标 0）。null value 可以有多个。`TreeMap` 不允许 null key（因为需要比较大小），`HashTable` 也不允许。

**Q：用 `int[]` 还是 `List<Integer>`？**  
A：纯数值计算、固定大小、性能敏感 → `int[]`（无装箱开销，内存连续）。需要动态增删、和其他集合配合、使用 Stream → `List<Integer>`。

**Q：`Comparator.comparing()` 怎么实现降序？**  
A：两种方式：

```java
// 方式一：reversed()
Comparator.comparing(Student::getGpa).reversed()
// 方式二：比较时交换参数顺序
(s1, s2) -> Double.compare(s2.getGpa(), s1.getGpa())
```

**Q：`Collections.sort()` 用的是什么排序算法？**  
A：底层是 `TimSort`——归并排序和插入排序的混合算法。时间复杂度 O(n log n)，对已部分排序的数据有优化，是稳定排序（相等元素相对顺序不变）。

**Q：`HashMap` 在多线程下会出什么问题？**  
A：JDK 7 及之前，并发扩容时可能形成环形链表导致 `get` 操作死循环。JDK 8 改用尾插法避免了环形链表，但并发 `put` 仍可能导致数据丢失。多线程场景应使用 `ConcurrentHashMap`。
