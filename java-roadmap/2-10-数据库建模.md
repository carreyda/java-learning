## 1. 需求分析

博客系统需要支持以下核心功能：

```
用户模块：注册、登录、个人信息管理
文章模块：发布、编辑、分类、标签、草稿/发布状态管理
评论模块：文章评论、评论回复（二级）
互动模块：文章点赞、收藏
标签模块：标签管理、文章多标签
分类模块：单级或多级分类
统计模块：浏览量、点赞数、评论数
```

---

## 2. 实体识别与 ER 图

### 核心实体

```
用户（User）
文章（Article）
分类（Category）
标签（Tag）
评论（Comment）
```

### 关系梳理

```
用户 ──发布──► 文章        （一对多）
文章 ──属于──► 分类        （多对一，一篇文章一个分类）
文章 ──拥有──► 标签        （多对多，通过 article_tag 中间表）
用户 ──发表──► 评论        （一对多）
文章 ──拥有──► 评论        （一对多）
评论 ──回复──► 评论        （自关联，parent_id）
用户 ──点赞──► 文章        （多对多，通过 article_like 中间表）
用户 ──收藏──► 文章        （多对多，通过 article_favorite 中间表）
```

### ER 图（文字描述）

```
┌─────────────┐       ┌─────────────────┐       ┌─────────────┐
│    user     │       │    article      │       │  category   │
│─────────────│       │─────────────────│       │─────────────│
│ id (PK)     │──1──N─│ id (PK)         │──N──1─│ id (PK)     │
│ username    │       │ title           │       │ name        │
│ email       │       │ content         │       │ parent_id   │
│ password    │       │ author_id (FK)  │       │ sort_order  │
│ nickname    │       │ category_id (FK)│       └─────────────┘
│ avatar      │       │ status          │

└─────────────┘       │ comment_count   │       │─────────────│
       │              │ is_top          │──N──M─│ id (PK)     │
       │              │ created_at      │       │ name        │
       │              └─────────────────┘       │ article_cnt │
       │                      │                 └─────────────┘
       │                      │ 1
```

## 3. 表结构设计

### 设计原则

```
1. 所有表都有 id（BIGINT AUTO_INCREMENT）、created_at、updated_at
2. 字符集统一 utf8mb4，支持 emoji
3. 软删除：敏感数据加 is_deleted 字段（0=正常，1=已删除）
4. 状态字段用 TINYINT 或 VARCHAR（枚举含义写在 COMMENT 里）
5. 冗余统计字段（view_count、like_count、comment_count）避免实时 COUNT
6. 外键约束视情况：学习阶段加上，高并发生产环境通常去掉（改为应用层保证）
```

## 4. 完整建表 SQL

把以下 SQL 保存为 `src/main/resources/schema.sql`：

```sql
-- ============================================================
-- 博客系统数据库初始化脚本
-- 数据库：blog_dev
-- 字符集：utf8mb4
-- ============================================================

CREATE DATABASE IF NOT EXISTS blog_dev
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE blog_dev;

-- ============================================================
-- 用户表
-- ============================================================
CREATE TABLE IF NOT EXISTS `user` (
    `id`            BIGINT       NOT NULL AUTO_INCREMENT         COMMENT '用户ID',
    `username`      VARCHAR(50)  NOT NULL                        COMMENT '用户名（唯一）',
    `email`         VARCHAR(100) NOT NULL                        COMMENT '邮箱（唯一）',
    `password_hash` VARCHAR(255) NOT NULL                        COMMENT '密码哈希（BCrypt）',
    `nickname`      VARCHAR(50)  DEFAULT NULL                    COMMENT '昵称',
    `avatar`        VARCHAR(500) DEFAULT NULL                    COMMENT '头像URL',
    `bio`           VARCHAR(500) DEFAULT NULL                    COMMENT '个人简介',
    `role`          VARCHAR(20)  NOT NULL DEFAULT 'USER'         COMMENT '角色：USER/ADMIN',
    `status`        TINYINT      NOT NULL DEFAULT 1              COMMENT '状态：1=正常 0=禁用',
    `is_deleted`    TINYINT      NOT NULL DEFAULT 0              COMMENT '是否删除：0=否 1=是',
    `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
    `updated_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
                                 ON UPDATE CURRENT_TIMESTAMP     COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_username` (`username`),
    UNIQUE KEY `uk_email` (`email`),
    INDEX `idx_status` (`status`, `is_deleted`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';


-- ============================================================
-- 分类表（支持二级分类）
-- ============================================================
CREATE TABLE IF NOT EXISTS `category` (
    `id`          INT          NOT NULL AUTO_INCREMENT           COMMENT '分类ID',
    `name`        VARCHAR(50)  NOT NULL                          COMMENT '分类名称',
    `slug`        VARCHAR(100) NOT NULL                          COMMENT 'URL友好名称（英文）',
    `description` VARCHAR(200) DEFAULT NULL                      COMMENT '分类描述',
    `parent_id`   INT          DEFAULT NULL                      COMMENT '父分类ID，NULL=顶级分类',
    `sort_order`  INT          NOT NULL DEFAULT 0                COMMENT '排序（升序）',
    `article_cnt` INT          NOT NULL DEFAULT 0                COMMENT '文章数量（冗余）',
    `is_deleted`  TINYINT      NOT NULL DEFAULT 0                COMMENT '是否删除',
    `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_slug` (`slug`),
    INDEX `idx_parent_id` (`parent_id`),
    INDEX `idx_sort` (`sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文章分类表';


-- ============================================================
-- 标签表
-- ============================================================
CREATE TABLE IF NOT EXISTS `tag` (
    `id`          INT          NOT NULL AUTO_INCREMENT           COMMENT '标签ID',
    `name`        VARCHAR(50)  NOT NULL                          COMMENT '标签名称',
    `slug`        VARCHAR(100) NOT NULL                          COMMENT 'URL友好名称',
    `article_cnt` INT          NOT NULL DEFAULT 0                COMMENT '使用该标签的文章数（冗余）',
    `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_name` (`name`),
    UNIQUE KEY `uk_slug` (`slug`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='标签表';


-- ============================================================
-- 文章表
-- ============================================================
CREATE TABLE IF NOT EXISTS `article` (
    `id`            BIGINT       NOT NULL AUTO_INCREMENT         COMMENT '文章ID',
    `title`         VARCHAR(200) NOT NULL                        COMMENT '文章标题',
    `content`       LONGTEXT     NOT NULL                        COMMENT '文章正文（Markdown）',
    `summary`       VARCHAR(500) DEFAULT NULL                    COMMENT '文章摘要（为空时自动截取）',
    `cover_image`   VARCHAR(500) DEFAULT NULL                    COMMENT '封面图URL',
    `author_id`     BIGINT       NOT NULL                        COMMENT '作者ID',
    `author_name`   VARCHAR(50)  NOT NULL                        COMMENT '作者名（冗余，避免 JOIN）',
    `category_id`   INT          DEFAULT NULL                    COMMENT '分类ID',
    `status`        VARCHAR(20)  NOT NULL DEFAULT 'DRAFT'        COMMENT '状态：DRAFT/PUBLISHED/ARCHIVED',
    `is_top`        TINYINT      NOT NULL DEFAULT 0              COMMENT '是否置顶：0=否 1=是',
    `is_original`   TINYINT      NOT NULL DEFAULT 1              COMMENT '是否原创：1=原创 0=转载',
    `view_count`    INT          NOT NULL DEFAULT 0              COMMENT '浏览量',
    `like_count`    INT          NOT NULL DEFAULT 0              COMMENT '点赞数',
    `comment_count` INT          NOT NULL DEFAULT 0              COMMENT '评论数',
    `word_count`    INT          NOT NULL DEFAULT 0              COMMENT '字数统计',
    `published_at`  DATETIME     DEFAULT NULL                    COMMENT '发布时间',
    `is_deleted`    TINYINT      NOT NULL DEFAULT 0              COMMENT '是否删除（软删除）',
    `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    INDEX `idx_author_id` (`author_id`),
    INDEX `idx_category_id` (`category_id`),
    INDEX `idx_status_deleted` (`status`, `is_deleted`),
    INDEX `idx_published_at` (`published_at`),
    INDEX `idx_is_top` (`is_top`),
    FULLTEXT INDEX `ft_title_content` (`title`, `content`)  -- 全文搜索
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文章表';


-- ============================================================
-- 文章-标签关联表（多对多）
-- ============================================================
CREATE TABLE IF NOT EXISTS `article_tag` (
    `article_id`  BIGINT  NOT NULL  COMMENT '文章ID',
    `tag_id`      INT     NOT NULL  COMMENT '标签ID',
    `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`article_id`, `tag_id`),  -- 复合主键，自带唯一索引
    INDEX `idx_tag_id` (`tag_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文章标签关联表';


-- ============================================================
-- 评论表（支持二级回复）
-- ============================================================
CREATE TABLE IF NOT EXISTS `comment` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT           COMMENT '评论ID',
    `article_id`  BIGINT       NOT NULL                          COMMENT '文章ID',
    `user_id`     BIGINT       NOT NULL                          COMMENT '评论者ID',
    `user_name`   VARCHAR(50)  NOT NULL                          COMMENT '评论者名（冗余）',
    `user_avatar` VARCHAR(500) DEFAULT NULL                      COMMENT '评论者头像（冗余）',
    `parent_id`   BIGINT       DEFAULT NULL                      COMMENT '父评论ID（NULL=顶级评论）',
    `reply_to_id` BIGINT       DEFAULT NULL                      COMMENT '回复的目标评论ID（用于 @某人）',
    `content`     TEXT         NOT NULL                          COMMENT '评论内容',
    `like_count`  INT          NOT NULL DEFAULT 0                COMMENT '点赞数',
    `is_deleted`  TINYINT      NOT NULL DEFAULT 0                COMMENT '是否删除',
    `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    INDEX `idx_article_id` (`article_id`, `is_deleted`),
    INDEX `idx_user_id` (`user_id`),
    INDEX `idx_parent_id` (`parent_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='评论表';


-- ============================================================
-- 文章点赞表
-- ============================================================
CREATE TABLE IF NOT EXISTS `article_like` (
    `user_id`     BIGINT   NOT NULL   COMMENT '用户ID',
    `article_id`  BIGINT   NOT NULL   COMMENT '文章ID',
    `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`user_id`, `article_id`),  -- 复合主键防重复点赞
    INDEX `idx_article_id` (`article_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文章点赞表';


-- ============================================================
-- 文章收藏表
-- ============================================================
CREATE TABLE IF NOT EXISTS `article_favorite` (
    `user_id`     BIGINT   NOT NULL   COMMENT '用户ID',
    `article_id`  BIGINT   NOT NULL   COMMENT '文章ID',
    `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`user_id`, `article_id`),
    INDEX `idx_article_id` (`article_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文章收藏表';
```

## 6. 设计决策说明

### 6.1 为什么冗余 author_name

```sql
-- 方案A：不冗余，每次查文章列表都 JOIN user 表
SELECT a.title, u.nickname FROM article a JOIN user u ON a.author_id = u.id;

-- 方案B：冗余 author_name，查文章列表不需要 JOIN
SELECT a.title, a.author_name FROM article;

-- 选方案B的理由：
-- 1. 文章列表是最高频的查询，少一个 JOIN 性能显著提升
-- 2. 用户改昵称的频率极低（不是实时性要求高的操作）
-- 3. 昵称变更时，通过后台异步任务批量更新 author_name
```

### 6.2 为什么保留 like_count / comment_count

```sql
-- 方案A：实时 COUNT
SELECT COUNT(*) FROM article_like WHERE article_id = 1;  -- 每次都要扫描
SELECT COUNT(*) FROM comment WHERE article_id = 1 AND is_deleted = 0;

-- 方案B：冗余统计字段
SELECT like_count, comment_count FROM article WHERE id = 1;  -- 直接读取

-- 选方案B理由：
-- 文章详情和列表都需要展示这些数字，实时 COUNT 在高并发下压力大
-- 通过事务保证：点赞时同步 +1，取消点赞时 -1
```

### 6.3 评论为什么只支持二级

```sql
-- parent_id 设计只支持二级评论（顶级评论 + 直接回复）
-- 不做无限嵌套的原因：
-- 1. UI 展示上，超过二级嵌套体验很差（微博/微信评论都是二级）
-- 2. 数据库设计简单，查询无需递归
-- 3. reply_to_id 记录回复的目标，前端可以展示 "回复@某人" 的效果
```

### 6.4 软删除策略

```
is_deleted = 0：正常
is_deleted = 1：已删除（不展示给用户，但数据保留）

MyBatis Plus 的 @TableLogic 注解会自动：
- 查询时加 WHERE is_deleted = 0
- 删除时改为 UPDATE SET is_deleted = 1
（2-12 节会详细讲）
```
