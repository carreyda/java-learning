## 1. 为什么需要参数校验

```java
// 没有参数校验的问题
@PostMapping("/users")
public Result<UserVO> create(@RequestBody CreateUserDTO dto) {
    // dto.getUsername() 可能是 null、空字符串、或 10000 个字符
    // dto.getEmail() 可能是随便一个字符串，根本不是邮箱格式
    // dto.getAge() 可能是 -1 或 999
    // 这些问题如果不检查，会产生脏数据甚至系统崩溃
    userService.createUser(dto);
}
```

**参数校验的两个层次：**

```
格式校验（参数层）：空不空、长度对不对、格式对不对
  → 用 Spring Validation 注解，框架自动完成

业务校验（Service 层）：用户名是否已被占用、余额是否充足
  → 写在 Service 里，抛出 BusinessException
```

本节重点是格式校验，业务校验已在 2-05 中介绍。

## 3. 常用校验注解

### 3.1 非空校验

```java
public class CreateUserDTO {
    @NotNull(message = "用户名不能为 null")
    private String username;

    @NotEmpty(message = "邮箱不能为空")  // 不为 null 且不为空字符串
    private String email;

    @NotBlank(message = "密码不能为空白") // 不为 null、不为空、不为纯空格
    private String password;

    @NotEmpty(message = "标签不能为空")
    private List<String> tags;
}
```

**三者区别：**

| 注解        | null | ""  | " " |
| ----------- | ---- | --- | --- |
| `@NotNull`  | ❌   | ✅  | ✅  |
| `@NotEmpty` | ❌   | ❌  | ✅  |
| `@NotBlank` | ❌   | ❌  | ❌  |

字符串用 `@NotBlank`，集合/数组用 `@NotEmpty`，其他对象用 `@NotNull`。

### 3.2 长度与范围

```java
public class CreateUserDTO {
    @Size(min = 3, max = 20, message = "用户名长度 3-20 字符")
    private String username;

    @Length(min = 6, max = 20, message = "密码长度 6-20 字符")  // Hibernate Validator 扩展
    private String password;

    @Min(value = 18, message = "年龄不能小于 18")
    @Max(value = 120, message = "年龄不能大于 120")
    private Integer age;

    @DecimalMin(value = "0.01", message = "金额最小 0.01")
    @DecimalMax(value = "999999.99", message = "金额最大 999999.99")
    private BigDecimal amount;

    @Positive(message = "数量必须是正数")
    private Integer quantity;

    @PositiveOrZero(message = "库存不能为负数")
    private Integer stock;
}
```

### 3.3 格式校验

```java
public class CreateUserDTO {
    @Email(message = "邮箱格式不正确")
    private String email;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String phone;

    @URL(message = "URL 格式不正确")
    private String website;

    @Past(message = "生日必须是过去的日期")
    private LocalDate birthday;

    @Future(message = "预约时间必须是未来的时间")
    private LocalDateTime appointmentTime;

    @PastOrPresent(message = "创建时间不能是未来")
    private LocalDateTime createdAt;
}
```

### 3.4 集合与嵌套

```java
public class CreateOrderDTO {

    @Size(max = 100, message = "单次最多 100 个商品")
```

## 4. 在 Controller 中启用校验

### 4.1 校验请求体

```java
@PostMapping
public Result<UserVO> create(
    @RequestBody @Valid CreateUserDTO dto  // @Valid 触发校验
) {
    return Result.ok(userService.createUser(dto));
}
```

### 4.2 校验路径参数和查询参数

```java
@Validated  // 类级别注解，开启方法参数校验
@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping("/{id}")
    public Result<UserVO> getById(
        @PathVariable @Positive(message = "ID 必须是正数") Long id
    ) { ... }

    @GetMapping
    public Result<List<UserVO>> list(
        @RequestParam(defaultValue = "1") @Min(1) Integer page,
        @RequestParam(defaultValue = "10") @Max(100) Integer size
    ) { ... }
}
```

> ⚠️ `@Valid` 用于触发**对象**内部的校验，`@Validated` 用于方法参数上的直接注解校验（如 `@Min`、`@NotBlank`）。两者可以混用。

## 5. 分组校验

同一个 DTO 在创建和更新时校验规则不同（如创建时用户名必填，更新时可选）：

### 5.1 定义分组接口

```java
// 校验分组接口（空接口，只用于标记）
public interface ValidationGroups {
    interface Create {}   // 创建时的校验组
    interface Update {}   // 更新时的校验组
}
```

### 5.2 在 DTO 上指定分组

```java
@Data
public class UserDTO {

    // 只在创建时校验（更新时可以不传）
    @NotBlank(message = "用户名不能为空", groups = ValidationGroups.Create.class)
    @Size(min = 3, max = 20, message = "用户名长度 3-20", groups = ValidationGroups.Create.class)
    private String username;

    // 创建和更新都校验
    @Email(message = "邮箱格式不正确",
           groups = {ValidationGroups.Create.class, ValidationGroups.Update.class})
    private String email;

    // 只在创建时校验
    @NotBlank(message = "密码不能为空", groups = ValidationGroups.Create.class)
    @Length(min = 6, max = 20, message = "密码长度 6-20", groups = ValidationGroups.Create.class)
    private String password;

    // 两者都校验
    @Min(value = 18, message = "年龄不能小于 18",
         groups = {ValidationGroups.Create.class, ValidationGroups.Update.class})
    private Integer age;
}
```

### 5.3 在 Controller 中指定使用哪个分组

```java
@RestController
@RequestMapping("/api/users")
public class UserController {

    // 创建：使用 Create 组的校验规则
    @PostMapping
    public Result<UserVO> create(
        @RequestBody @Validated(ValidationGroups.Create.class) UserDTO dto
    ) {
        return Result.ok(userService.createUser(dto));
    }

    // 更新：使用 Update 组的校验规则
    @PutMapping("/{id}")
    public Result<UserVO> update(
        @PathVariable Long id,
        @RequestBody @Validated(ValidationGroups.Update.class) UserDTO dto
    ) {
        return Result.ok(userService.updateUser(id, dto));
    }
}
```

## 6. 自定义校验注解

内置注解不够用时，可以自定义：

### 6.1 自定义手机号校验

```java
// Step 1：定义注解
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = PhoneValidator.class)  // 指定校验器
@Documented
public @interface Phone {
    String message() default "手机号格式不正确";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

// Step 2：实现校验器
public class PhoneValidator implements ConstraintValidator<Phone, String> {

    private static final Pattern PHONE_PATTERN = Pattern.compile("^1[3-9]\\d{9}$");

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null || value.isBlank()) {
            return true;  // null 由 @NotBlank 处理，这里只校验格式
        }
        return PHONE_PATTERN.matcher(value).matches();
    }
}

// Step 3：使用
public class CreateUserDTO {
    @Phone
    private String phone;
}
```

### 6.2 自定义枚举值校验

```java
// 校验字符串必须是枚举中的某个值
@Target({ElementType.FIELD})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = EnumValueValidator.class)
public @interface EnumValue {
    String message() default "值不合法";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
    Class<? extends Enum<?>> enumClass();  // 指定枚举类
}

public class EnumValueValidator implements ConstraintValidator<EnumValue, String> {

    private List<String> acceptedValues;

    @Override
    public void initialize(EnumValue annotation) {
        acceptedValues = Arrays.stream(annotation.enumClass().getEnumConstants())
            .map(Enum::name)
            .collect(Collectors.toList());
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        return value == null || acceptedValues.contains(value);
    }
}

// 使用
public enum ArticleStatus { DRAFT, PUBLISHED, ARCHIVED }

public class CreateArticleDTO {
    @EnumValue(enumClass = ArticleStatus.class, message = "文章状态不合法")
    private String status;
}
```

### 6.3 跨字段校验（类级别）

```java
// 校验密码和确认密码一致
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = PasswordMatchValidator.class)
public @interface PasswordMatch {
    String message() default "两次密码不一致";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
    String password();           // 密码字段名
    String confirmPassword();    // 确认密码字段名
}

public class PasswordMatchValidator
        implements ConstraintValidator<PasswordMatch, Object> {

    private String passwordField;
    private String confirmPasswordField;

    @Override
    public void initialize(PasswordMatch annotation) {
        this.passwordField = annotation.password();
        this.confirmPasswordField = annotation.confirmPassword();
    }

    @Override
    public boolean isValid(Object obj, ConstraintValidatorContext context) {
        try {
            Object password = new PropertyDescriptor(passwordField, obj.getClass())
                .getReadMethod().invoke(obj);
            Object confirm = new PropertyDescriptor(confirmPasswordField, obj.getClass())
                .getReadMethod().invoke(obj);
            return Objects.equals(password, confirm);
        } catch (Exception e) {
            return false;
        }
    }
}

// 使用（注解加在类上）
@Data
@PasswordMatch(password = "password", confirmPassword = "confirmPassword",
               message = "两次密码输入不一致")
public class RegisterDTO {
    @NotBlank
    private String username;

    @NotBlank
    @Length(min = 6)
    private String password;

    @NotBlank
    private String confirmPassword;
}
```

## 7. 完善全局异常处理

把 2-04 的 GlobalExceptionHandler 完善为生产级别：

```java
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    // ===== 参数校验异常 =====

    // @Valid 或 @Validated 校验 @RequestBody 失败
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Map<String, String>> handleValidationFailed(
            MethodArgumentNotValidException e) {
        // 收集所有字段的错误信息，返回 Map
        Map<String, String> errors = new LinkedHashMap<>();
        e.getBindingResult().getFieldErrors()
            .forEach(error -> errors.put(error.getField(), error.getDefaultMessage()));
        log.warn("参数校验失败：{}", errors);
        return Result.fail(400, "参数校验失败", errors);
    }

    // @Validated 校验方法参数（@PathVariable、@RequestParam）失败
    @ExceptionHandler(ConstraintViolationException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleConstraintViolation(ConstraintViolationException e) {
        String message = e.getConstraintViolations().stream()
            .map(ConstraintViolation::getMessage)
            .collect(Collectors.joining("; "));
        log.warn("约束违反：{}", message);
        return Result.badRequest(message);
    }

    // 请求体 JSON 格式错误（无法解析）
    @ExceptionHandler(HttpMessageNotReadableException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleMessageNotReadable(HttpMessageNotReadableException e) {
        log.warn("请求体解析失败：{}", e.getMessage());
        return Result.badRequest("请求体格式错误，请检查 JSON 格式");
    }

    // 请求方法不支持（如 POST 接口收到了 GET 请求）
    @ExceptionHandler(HttpRequestMethodNotSupportedException.class)
    @ResponseStatus(HttpStatus.METHOD_NOT_ALLOWED)
    public Result<Void> handleMethodNotSupported(HttpRequestMethodNotSupportedException e) {
        return Result.fail(405, "不支持的请求方法：" + e.getMethod());
    }

    // ===== 业务异常 =====

    @ExceptionHandler(ResourceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public Result<Void> handleNotFound(ResourceNotFoundException e) {
        log.info("资源不存在：{}", e.getMessage());
        return Result.notFound(e.getMessage());
    }

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<Result<Void>> handleBusiness(BusinessException e) {
        log.warn("业务异常：code={}, message={}", e.getCode(), e.getMessage());
        HttpStatus status = HttpStatus.resolve(e.getCode());
        if (status == null) status = HttpStatus.BAD_REQUEST;
        return ResponseEntity.status(status).body(Result.fail(e.getCode(), e.getMessage()));
    }

    // ===== 兜底异常 =====

    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public Result<Void> handleException(Exception e, HttpServletRequest request) {
        log.error("未处理的异常，请求：{} {}", request.getMethod(), request.getRequestURI(), e);
        // 生产环境不暴露详细错误信息
        return Result.serverError("服务器内部错误，请稍后重试");
    }
}
```

### 修改 Result 类支持 data

```java
@Data
public class Result<T> {
    private int code;
    private String message;
    private T data;

    private Result(int code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
    }

    public static <T> Result<T> ok(T data) { return new Result<>(200, "success", data); }
    public static <T> Result<T> ok() { return new Result<>(200, "success", null); }
    public static <T> Result<T> fail(int code, String message) { return new Result<>(code, message, null); }
    // 新增：支持返回错误详情
    public static <T> Result<T> fail(int code, String message, T data) { return new Result<>(code, message, data); }
    public static <T> Result<T> badRequest(String message) { return fail(400, message); }
    public static <T> Result<T> notFound(String message) { return fail(404, message); }
    public static <T> Result<T> serverError(String message) { return fail(500, message); }
}
```

### 8.1 错误码设计

```java
public enum ErrorCode {
    // 通用错误
    SUCCESS(200, "success"),
    BAD_REQUEST(400, "请求参数错误"),
    UNAUTHORIZED(401, "未登录或 Token 已过期"),
    FORBIDDEN(403, "无权限访问"),
    NOT_FOUND(404, "资源不存在"),
    METHOD_NOT_ALLOWED(405, "请求方法不支持"),
    CONFLICT(409, "数据冲突"),
    TOO_MANY_REQUESTS(429, "请求过于频繁"),
    SERVER_ERROR(500, "服务器内部错误"),

    // 用户相关（1001xx）
    USER_NOT_FOUND(100101, "用户不存在"),
    USERNAME_ALREADY_EXISTS(100102, "用户名已被占用"),
    EMAIL_ALREADY_EXISTS(100103, "邮箱已被注册"),
    WRONG_PASSWORD(100104, "密码错误"),
    ACCOUNT_DISABLED(100105, "账号已被禁用"),

    // 文章相关（1002xx）
    ARTICLE_NOT_FOUND(100201, "文章不存在"),
    ARTICLE_ALREADY_PUBLISHED(100202, "文章已发布，不能重复发布"),
    NO_PERMISSION_TO_EDIT(100203, "无权限编辑此文章");

    private final int code;
    private final String message;

    ErrorCode(int code, String message) {
        this.code = code;
        this.message = message;
    }

    public int getCode() { return code; }
    public String getMessage() { return message; }
```

### 8.2 基于错误码的异常类

```java
// 基类
public class AppException extends RuntimeException {
    private final int code;
    private final String message;

    public AppException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
        this.message = errorCode.getMessage();
    }

    public AppException(ErrorCode errorCode, String detail) {
        super(errorCode.getMessage() + "：" + detail);
        this.code = errorCode.getCode();
        this.message = errorCode.getMessage() + "：" + detail;
    }

    public AppException(ErrorCode errorCode, Throwable cause) {
        super(errorCode.getMessage(), cause);
        this.code = errorCode.getCode();
        this.message = errorCode.getMessage();
    }

    public int getCode() { return code; }

    @Override
    public String getMessage() { return message; }
}

// 具体业务异常（按需定义）
public class UserNotFoundException extends AppException {
    public UserNotFoundException(Long id) {
        super(ErrorCode.USER_NOT_FOUND, "id=" + id);
    }
    public UserNotFoundException(String username) {
        super(ErrorCode.USER_NOT_FOUND, "username=" + username);
    }
}

public class UsernameAlreadyExistsException extends AppException {
    public UsernameAlreadyExistsException(String username) {
        super(ErrorCode.USERNAME_ALREADY_EXISTS, username);
    }
}
```


## 常见问题

**Q：`@Valid` 和 `@Validated` 怎么选？**  
A：`@Valid` 是 Jakarta 标准注解，`@Validated` 是 Spring 扩展，支持分组校验。实际项目中：用 `@Valid` 触发嵌套对象校验，用 `@Validated` 做分组校验或方法参数直接校验。两者可以混用。

**Q：校验失败只提示第一个错误还是所有错误？**  
A：默认会收集所有字段的所有错误（Fast-fail 模式是关闭的）。如果想校验失败后立即停止（只报第一个错误），可以自定义 Validator 配置开启 failFast 模式。

**Q：自定义 Validator 中能注入 Spring Bean 吗？**  
A：可以，只要把 Validator 类注册为 Spring Bean 或者让框架管理（在 Validator 类上加 `@Component`，但实际上 Spring 的 Validator 工厂会自动注入），就可以用 `@Autowired` 注入其他 Bean。

**Q：`@NotBlank` 和 `@NotNull` 能同时加吗？**  
A：可以，但 `@NotBlank` 已经包含了 null 检查，等同于 `@NotNull + @NotEmpty + 去空格`。同时加 `@NotBlank` 和 `@NotNull` 是冗余的，只加 `@NotBlank` 就够了。
