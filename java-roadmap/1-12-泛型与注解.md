## 1. 泛型深入

### 1.1 泛型的本质：类型参数化

泛型让类、接口、方法的**类型**变成参数，在使用时再指定具体类型：

```java
// 没有泛型：只能存 Object，取出时要强转，类型不安全
List list = new ArrayList();
list.add("hello");
list.add(123);
String s = (String) list.get(0);  // 强转，运行时可能 ClassCastException

// 有泛型：类型由编译器保证，无需强转
List<String> list = new ArrayList<>();
list.add("hello");
// list.add(123);  ❌ 编译报错
String s = list.get(0);  // ✅ 直接赋值
```

### 1.2 泛型擦除

Java 的泛型是**编译期机制**，运行时泛型类型信息会被擦除：

```java
List<String> strings = new ArrayList<>();
List<Integer> ints = new ArrayList<>();

// 运行时两者类型完全一样，都是 ArrayList
System.out.println(strings.getClass() == ints.getClass());  // true

// 无法在运行时获取泛型参数类型
// strings instanceof List<String>  ❌ 编译报错
strings instanceof List  // ✅ 只能这样
```

这是 Java 泛型与 C++ 模板的重要区别，理解擦除能解释很多"奇怪"的限制。

## 2. 通配符与边界

### 2.1 无界通配符 `<?>`

表示"任意类型"，用于只读场景：

```java
// 打印任意类型 List 的元素
public static void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}

printList(new ArrayList<String>());   // ✅
printList(new ArrayList<Integer>());  // ✅
printList(new ArrayList<Double>());   // ✅

// ⚠️ 不能往 List<?> 里添加元素（除了 null）
// list.add("hello");  ❌ 编译报错，类型未知，无法保证安全
```

### 2.2 上界通配符 `<? extends T>`

表示"T 或 T 的子类"，**只读**（生产者）：

```java
// 计算任意数字列表的总和（Number 及其子类：Integer、Double、Long...）
public static double sum(List<? extends Number> list) {
    double total = 0;
    for (Number n : list) {
        total += n.doubleValue();
    }
    return total;
}

sum(new ArrayList<Integer>(List.of(1, 2, 3)));    // ✅
sum(new ArrayList<Double>(List.of(1.5, 2.5)));    // ✅
// sum(new ArrayList<String>(...));               ❌ String 不是 Number 子类

// ⚠️ 不能往上界通配符列表里添加元素
// list.add(1.0);  ❌ 编译报错
```

### 2.3 下界通配符 `<? super T>`

表示"T 或 T 的父类"，**只写**（消费者）：

```java
// 向列表中添加整数（Integer 或其父类 Number、Object 的 List 都接受）
public static void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
    list.add(3);
}

List<Integer> ints = new ArrayList<>();
List<Number> nums = new ArrayList<>();
List<Object> objs = new ArrayList<>();

addNumbers(ints);  // ✅
addNumbers(nums);  // ✅
addNumbers(objs);  // ✅
```

### 2.4 PECS 原则

> **Producer Extends, Consumer Super（生产者用 extends，消费者用 super）**

```java
// 从集合中读取数据（生产者）→ extends
public static <T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {
        dest.add(item);
    }
}

List<Integer> source = List.of(1, 2, 3);
List<Number> target = new ArrayList<>();
copy(source, target);  // Integer extends Number，Number super Integer
```

## 3. 泛型方法与泛型类

### 3.1 泛型方法

```java
// 在返回值前声明类型参数 <T>
public static <T> T getFirst(List<T> list) {
    if (list == null || list.isEmpty()) return null;
    return list.get(0);
}

// 多个类型参数
public static <K, V> Map<V, K> invertMap(Map<K, V> map) {
    Map<V, K> result = new HashMap<>();
    map.forEach((k, v) -> result.put(v, k));
    return result;
}

// 使用
String first = getFirst(List.of("a", "b", "c"));  // "a"
Integer num = getFirst(List.of(1, 2, 3));           // 1

Map<String, Integer> original = Map.of("a", 1, "b", 2);
Map<Integer, String> inverted = invertMap(original);  // {1=a, 2=b}
```

### 3.2 泛型类

```java
// 通用的键值对（Pair）
public class Pair<A, B> {
    private final A first;
    private final B second;

    public Pair(A first, B second) {
        this.first = first;
        this.second = second;
    }

    public A getFirst() { return first; }
    public B getSecond() { return second; }

    @Override
    public String toString() {
        return "(" + first + ", " + second + ")";
    }
}

// 使用
Pair<String, Integer> nameAge = new Pair<>("张三", 25);
Pair<Double, Double> point = new Pair<>(3.14, 2.71);
System.out.println(nameAge);  // (张三, 25)
```

## 4. 注解基础

注解（Annotation）是一种元数据，用于给代码附加额外信息，可以被编译器或运行时读取。

### 4.1 内置注解

```java
// @Override：告诉编译器这是重写父类方法，拼写错误时报错
@Override
public String toString() { return "..."; }

// @Deprecated：标记方法已过时，使用时编译器会警告
@Deprecated
public void oldMethod() { ... }

// @SuppressWarnings：压制编译器警告
@SuppressWarnings("unchecked")
List list = new ArrayList();  // 原本会有 unchecked 警告

// @FunctionalInterface：标记接口是函数式接口（只有一个抽象方法）
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);
}
```

### 4.2 元注解

用来注解注解的注解（标注注解自身的属性）：

| 元注解        | 作用                                       |
| ------------- | ------------------------------------------ |
| `@Target`     | 指定注解可以用在哪里（类、方法、字段...）  |
| `@Retention`  | 指定注解保留到哪个阶段（源码/编译/运行时） |
| `@Documented` | 是否包含在 Javadoc 中                      |
| `@Inherited`  | 子类是否继承父类的注解                     |

```java
import java.lang.annotation.*;

@Target(ElementType.METHOD)          // 只能用在方法上
@Retention(RetentionPolicy.RUNTIME)  // 保留到运行时（可以通过反射读取）
@Documented
public @interface MyAnnotation {
    String value() default "";
}
```

**RetentionPolicy 说明：**

| 值        | 含义                             | 用途                             |
| --------- | -------------------------------- | -------------------------------- |
| `SOURCE`  | 只在源码中，编译时丢弃           | `@Override`、`@SuppressWarnings` |
| `CLASS`   | 保留到 .class 文件，运行时不可见 | 字节码处理工具                   |
| `RUNTIME` | 保留到运行时，可用反射读取       | Spring 注解、自定义框架          |

## 5. 自定义注解

### 5.1 定义注解

```java
import java.lang.annotation.*;

// 字段校验注解：标记字段不能为空
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NotNull {
    String message() default "字段不能为空";
}

// 字段校验注解：标记字符串长度范围
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Length {
    int min() default 0;
    int max() default Integer.MAX_VALUE;
    String message() default "长度不符合要求";
}

// 方法日志注解：标记需要记录调用日志的方法
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Log {
    String value() default "";  // 日志描述
}
```

### 5.2 在类上使用注解

```java
public class UserForm {

    @NotNull(message = "用户名不能为空")
    @Length(min = 2, max = 20, message = "用户名长度必须在 2-20 之间")
    private String username;

    @NotNull(message = "密码不能为空")
    @Length(min = 6, max = 20, message = "密码长度必须在 6-20 之间")
    private String password;

    @NotNull(message = "邮箱不能为空")
    private String email;

    // 构造、getter...
}
```

注解本身不会自动产生任何效果，需要通过**反射**来读取并处理。

## 6. 反射基础

反射（Reflection）允许程序在**运行时**获取类的信息（字段、方法、注解等）并动态操作。这是 Spring 依赖注入、MyBatis 结果映射等框架功能的底层实现。

### 6.1 获取 Class 对象

```java
// 三种方式获取 Class 对象
Class<String> c1 = String.class;                    // 方式一：类名.class
Class<?> c2 = "hello".getClass();                   // 方式二：对象.getClass()
Class<?> c3 = Class.forName("java.lang.String");    // 方式三：全限定类名（最灵活）

System.out.println(c1.getName());       // java.lang.String
System.out.println(c1.getSimpleName()); // String
System.out.println(c1.getPackageName()); // java.lang
```

### 6.2 获取类信息

```java
Class<?> clazz = Student.class;

// 获取所有字段（包括私有）
Field[] fields = clazz.getDeclaredFields();
for (Field field : fields) {
    System.out.println(field.getName() + " : " + field.getType().getSimpleName());
}

// 获取所有方法
Method[] methods = clazz.getDeclaredMethods();
for (Method method : methods) {
    System.out.println(method.getName());
}

// 获取构造方法
Constructor<?>[] constructors = clazz.getDeclaredConstructors();

// 获取父类和接口
Class<?> superClass = clazz.getSuperclass();
Class<?>[] interfaces = clazz.getInterfaces();
```

### 6.3 动态创建对象和调用方法

```java
// 动态创建对象
Class<?> clazz = Class.forName("model.Student");
Constructor<?> constructor = clazz.getDeclaredConstructor(
    String.class, String.class, int.class, String.class, String.class);
Object student = constructor.newInstance("S0001", "张三", 20, "男", "计算机");

// 动态调用方法
Method method = clazz.getDeclaredMethod("getName");
String name = (String) method.invoke(student);
System.out.println(name);  // 张三

// 动态设置私有字段的值
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);  // 突破 private 限制
field.set(student, "李四");
System.out.println(field.get(student));  // 李四
```

### 6.4 读取注解信息

```java
Class<?> clazz = UserForm.class;
Field[] fields = clazz.getDeclaredFields();

for (Field field : fields) {
    // 检查字段是否有 @NotNull 注解
    if (field.isAnnotationPresent(NotNull.class)) {
        NotNull annotation = field.getAnnotation(NotNull.class);
        System.out.println(field.getName() + " 不能为空：" + annotation.message());
    }

    // 检查是否有 @Length 注解
    if (field.isAnnotationPresent(Length.class)) {
        Length annotation = field.getAnnotation(Length.class);
        System.out.printf("%s 长度范围：%d-%d%n",
            field.getName(), annotation.min(), annotation.max());
    }
}
```

## 7. 反射 + 注解的实际应用

### 7.1 实现简单的字段校验器

```java
public class Validator {

    public static List<String> validate(Object obj) {
        List<String> errors = new ArrayList<>();
        Class<?> clazz = obj.getClass();

        for (Field field : clazz.getDeclaredFields()) {
            field.setAccessible(true);
            Object value = null;
            try {
                value = field.get(obj);
            } catch (IllegalAccessException e) {
                continue;
            }

            // 处理 @NotNull
            if (field.isAnnotationPresent(NotNull.class)) {
                if (value == null || value.toString().isBlank()) {
                    errors.add(field.getAnnotation(NotNull.class).message());
                }
            }

            // 处理 @Length
            if (field.isAnnotationPresent(Length.class) && value instanceof String str) {
                Length length = field.getAnnotation(Length.class);
                if (str.length() < length.min() || str.length() > length.max()) {
                    errors.add(length.message());
                }
            }
        }
        return errors;
    }
}
```

```java
// 使用校验器
UserForm form = new UserForm();
form.setUsername("张");  // 太短，不符合 min=2 的要求
form.setPassword(null);  // 为空

List<String> errors = Validator.validate(form);
errors.forEach(System.out::println);
// 用户名长度必须在 2-20 之间
// 密码不能为空
// 邮箱不能为空
```

这就是 Spring 的 `@Valid`、`@NotNull`、`@Size` 等注解的底层原理——只是框架的实现更完善。

### 7.2 Spring 注解预览

你在阶段二会大量用到这些注解，现在先认识一下：

```java
// Spring Boot 常见注解（阶段二会详细讲）
@Component        // 标记这是一个 Spring 管理的组件（Bean）
@Service          // 业务层组件
@Repository       // 数据访问层组件
@Controller       // Web 控制器
@RestController   // REST API 控制器

@Autowired        // 自动注入依赖（通过反射）
@Value("${key}")  // 注入配置值

@RequestMapping("/api")  // 映射 HTTP 请求路径
@GetMapping("/users")    // GET 请求
@PostMapping("/users")   // POST 请求

@Transactional    // 声明事务（通过 AOP + 反射实现）
```

Spring 框架在启动时扫描所有类，通过反射读取这些注解，然后自动完成对象的创建、注入、代理等操作。理解了反射和注解，Spring 的"魔法"就不神秘了。

## 8. 和 JavaScript 的对比

### 泛型 vs TypeScript 泛型

```typescript
// TypeScript 泛型（运行时类型信息保留）
function getFirst<T>(arr: T[]): T | null {
  return arr.length > 0 ? arr[0] : null;
}

const first = getFirst<string>(["a", "b"]); // "a"
```

```java
// Java 泛型（编译时擦除）
public static <T> T getFirst(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}

String first = getFirst(List.of("a", "b"));  // "a"
```

两者语法类似，但 TypeScript 的泛型信息在运行时保留，Java 的会被擦除。

### 注解 vs JS 装饰器

```typescript
// TypeScript 装饰器（类似 Java 注解）
@Component
class UserService {
    @Inject()
    private userRepo: UserRepository;

    @Log("获取用户")
    getUser(id: string) { ... }
}
```

```java
// Java 注解（Spring 中）
@Service
public class UserService {
    @Autowired
    private UserRepository userRepo;

    @Log("获取用户")
    public User getUser(String id) { ... }
}
```

概念非常相似。TypeScript 装饰器实际上参考了 Java 注解的设计。

### 反射 vs JS 动态特性

```javascript
// JS 天生动态，不需要反射
const obj = { name: "张三", age: 25 };
const key = "name";
console.log(obj[key]); // "张三"，动态访问属性

// 获取所有属性
Object.keys(obj); // ["name", "age"]
Object.values(obj); // ["张三", 25]
```

```java
// Java 静态类型，需要反射才能动态操作
Student student = new Student(...);
Field field = Student.class.getDeclaredField("name");
field.setAccessible(true);
System.out.println(field.get(student));  // "张三"
```

JS 的动态性是语言本身的特点，Java 通过反射模拟这种动态能力，但代价是代码繁琐且性能较低。

## 常见问题

**Q：泛型擦除会导致什么问题？**  
A：主要有三个限制：① 不能用 `new T()`（类型未知），② 不能用 `instanceof T`，③ 不能创建 `T[]` 数组。实际开发中遇到需要类型信息时，通常通过传入 `Class<T>` 参数来解决：

```java
public <T> T create(Class<T> clazz) throws Exception {
    return clazz.getDeclaredConstructor().newInstance();
}
```

**Q：`Class.forName()` 和 `.class` 有什么区别？**  
A：`.class` 是编译期确定的，需要在代码里写死类名。`Class.forName("类名")` 接受字符串，可以在运行时动态指定，更灵活，常用于插件化、配置驱动的场景。后者如果类名写错会在运行时抛 `ClassNotFoundException`。

**Q：`field.setAccessible(true)` 安全吗？**  
A：这会绕过 Java 的访问控制（`private`），是反射的"暴力"用法。框架内部大量使用，但自己写业务代码时应尽量避免。JDK 17+ 引入了模块系统，对跨模块的反射有了更严格的限制。

**Q：反射性能差，Spring 用反射不会很慢吗？**  
A：反射确实比直接调用慢（大约慢 10-100 倍），但 Spring 在启动时做了大量缓存，运行时直接走缓存，不是每次请求都调反射。现代 JVM 的 JIT 编译也会对热点反射调用做优化。总体来说性能影响在可接受范围内。
