## 1. 为什么需要多线程

现代 CPU 是多核的，单线程程序同一时刻只能用一个核心，浪费算力。多线程让程序可以：

- **并发执行**：多个任务交替进行（单核上的并发）
- **并行执行**：多个任务真正同时进行（多核上的并行）

**典型场景：**

```
后端服务器：每个请求一个线程，同时处理成千上万个请求
文件下载：下载时不阻塞界面，另一个线程处理 UI
数据处理：大数据集分片，多线程并行处理，最后合并结果
定时任务：后台线程定期执行清理、统计等任务
```

**进程 vs 线程：**

| 对比 | 进程                       | 线程                     |
| ---- | -------------------------- | ------------------------ |
| 定义 | 操作系统分配资源的基本单位 | CPU 调度的基本单位       |
| 内存 | 独立内存空间               | 共享所在进程的内存       |
| 开销 | 创建销毁开销大             | 轻量级                   |
| 通信 | 进程间通信（IPC）复杂      | 直接共享内存，但需要同步 |

一个 Java 程序就是一个进程，`main` 方法运行在主线程上，可以在程序内创建多个线程。

## 2. 线程的创建

### 2.1 方式一：继承 Thread 类

```java
public class MyThread extends Thread {
    private String taskName;

    public MyThread(String taskName) {
        this.taskName = taskName;
    }

    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(taskName + " 执行第 " + i + " 次，线程：" + Thread.currentThread().getName());
            try {
                Thread.sleep(100);  // 模拟耗时操作
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    }
}

// 使用
MyThread t1 = new MyThread("任务A");
MyThread t2 = new MyThread("任务B");
t1.start();  // 启动线程（不是调用 run()！）
t2.start();
```

> ⚠️ **必须调用 `start()`，不能直接调用 `run()`。**  
> 调用 `run()` 只是普通方法调用，在当前线程上顺序执行，不会创建新线程。

### 2.2 方式二：实现 Runnable 接口（推荐）

```java
public class MyTask implements Runnable {
    private String name;

    public MyTask(String name) {
        this.name = name;
    }

    @Override
    public void run() {
        System.out.println(name + " 正在运行，线程：" + Thread.currentThread().getName());
    }
}

// 使用
Thread t1 = new Thread(new MyTask("任务A"));
Thread t2 = new Thread(new MyTask("任务B"), "自定义线程名");  // 可以命名
t1.start();
t2.start();

// Lambda 简写（Runnable 是函数式接口）
Thread t3 = new Thread(() -> System.out.println("Lambda 任务"));
t3.start();
```

**为什么推荐 Runnable 而不是继承 Thread？**

- Java 单继承，继承 Thread 就不能继承其他类
- Runnable 只描述"任务"，Thread 负责"执行"，职责分离更合理
- 同一个 Runnable 可以被多个 Thread 复用

### 2.3 方式三：实现 Callable + FutureTask（有返回值）

前两种方式的 `run()` 方法没有返回值，也不能抛受检异常。`Callable` 解决了这个问题：

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

Callable<Integer> task = () -> {
    System.out.println("开始计算...");
    Thread.sleep(1000);
    return 42;  // 有返回值
};

FutureTask<Integer> futureTask = new FutureTask<>(task);
Thread thread = new Thread(futureTask);
thread.start();

// 主线程继续做其他事
System.out.println("主线程继续运行...");

// 需要结果时，get() 会阻塞直到子线程完成
Integer result = futureTask.get();
System.out.println("计算结果：" + result);  // 42
```

### 2.4 Thread 常用方法

```java
Thread t = new Thread(() -> { /* ... */ }, "myThread");

t.start();              // 启动线程
t.getName();            // 获取线程名
t.getId();              // 获取线程 ID
t.isAlive();            // 是否正在运行
t.getState();           // 获取线程状态

// 静态方法
Thread.currentThread(); // 获取当前线程
Thread.sleep(1000);     // 当前线程休眠 1 秒（毫秒）
Thread.yield();         // 提示让出 CPU 时间片

// join：等待某线程执行完
Thread downloader = new Thread(() -> downloadFile());
downloader.start();
downloader.join();  // 等 downloader 线程结束后，当前线程再继续
System.out.println("下载完成，开始处理...");

// 守护线程（后台线程）：所有非守护线程结束时，JVM 退出，守护线程也自动终止
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("心跳...");
        Thread.sleep(1000);
    }
});
daemon.setDaemon(true);  // 必须在 start() 前设置
daemon.start();
```

## 3. 线程的生命周期

```
NEW（新建）
  ↓ start()
RUNNABLE（可运行/运行中）
  ↓ 等待锁 / sleep / wait / IO
BLOCKED（阻塞）/ WAITING（等待）/ TIMED_WAITING（超时等待）
  ↓ 锁释放 / notify / 超时
RUNNABLE
  ↓ run() 结束 / 异常
TERMINATED（终止）
```

```java
Thread t = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
});

System.out.println(t.getState());  // NEW
t.start();
System.out.println(t.getState());  // RUNNABLE 或 TIMED_WAITING
t.join();
System.out.println(t.getState());  // TERMINATED
```

## 4. 线程安全问题

当多个线程**同时读写共享数据**时，会出现竞态条件（Race Condition）：

```java
public class Counter {
    private int count = 0;

    public void increment() {
        count++;  // 看似一行，实际是三步：读取 → 加一 → 写回
    }

    public int getCount() {
        return count;
    }
}

// 问题演示
Counter counter = new Counter();

Runnable task = () -> {
    for (int i = 0; i < 1000; i++) {
        counter.increment();
    }
};

Thread t1 = new Thread(task);
Thread t2 = new Thread(task);
t1.start();
t2.start();
t1.join();
t2.join();

// 预期结果：2000
// 实际结果：可能是 1536、1789 等，每次不同！
System.out.println(counter.getCount());
```

**原因：** `count++` 不是原子操作，分三步执行：

```
线程1 读取 count = 100
线程2 读取 count = 100  ← 线程1还没写回，线程2读到旧值
线程1 计算 100 + 1 = 101，写回
线程2 计算 100 + 1 = 101，写回  ← 两次 ++ 只增加了 1！
```

## 5. synchronized 同步

`synchronized` 保证同一时刻只有一个线程执行被保护的代码块。

### 5.1 同步方法

```java
public class SafeCounter {
    private int count = 0;

    // synchronized 方法：整个方法同一时刻只能一个线程执行
    public synchronized void increment() {
        count++;
    }

    public synchronized int getCount() {
        return count;
    }
}

// 现在结果稳定是 2000
SafeCounter counter = new SafeCounter();
Runnable task = () -> {
    for (int i = 0; i < 1000; i++) counter.increment();
};
Thread t1 = new Thread(task);
Thread t2 = new Thread(task);
t1.start(); t2.start();
t1.join(); t2.join();
System.out.println(counter.getCount());  // 2000，稳定
```

### 5.2 同步代码块

```java
public class SafeCounter {
    private int count = 0;
    private final Object lock = new Object();  // 锁对象

    public void increment() {
        // 只锁住需要同步的代码，锁的范围更小，性能更好
        synchronized (lock) {
            count++;
        }
        // 这里的代码不需要同步，可以并发执行
    }
}
```

### 5.3 synchronized 的局限性

```java
// synchronized 是悲观锁：认为一定会冲突，每次都加锁
// 在低并发场景下性能损耗较大

// 不能中断等待锁的线程
// 不能设置超时时间
// 只能关联一个条件变量（wait/notify）
```

### 5.4 死锁

```java
// 死锁：两个线程互相等待对方持有的锁

Object lockA = new Object();
Object lockB = new Object();

Thread t1 = new Thread(() -> {
    synchronized (lockA) {
        System.out.println("T1 持有 A，等待 B");
        synchronized (lockB) {  // 等待 T2 释放 B
            System.out.println("T1 同时持有 A 和 B");
        }
    }
});

Thread t2 = new Thread(() -> {
    synchronized (lockB) {
        System.out.println("T2 持有 B，等待 A");
        synchronized (lockA) {  // 等待 T1 释放 A
            System.out.println("T2 同时持有 A 和 B");
        }
    }
});

t1.start();
t2.start();
// 程序卡死！T1 等 B，T2 等 A，互相等待，永远无法继续
```

**避免死锁的原则：**

- 保持加锁顺序一致（都先锁 A 再锁 B）
- 减少锁的嵌套
- 使用 `tryLock()` 设置超时时间

## 6. volatile 关键字

`volatile` 保证变量的**可见性**——一个线程修改了变量，其他线程立即能看到最新值：

```java
public class StopExample {
    // 没有 volatile：主线程修改 running，子线程可能看不到
    private volatile boolean running = true;

    public void start() {
        Thread worker = new Thread(() -> {
            while (running) {  // 如果没有 volatile，可能永远读不到 false
                System.out.println("工作中...");
                try { Thread.sleep(500); } catch (InterruptedException e) { break; }
            }
            System.out.println("线程停止");
        });
        worker.start();
    }

    public void stop() {
        running = false;  // 修改后，worker 线程能立即看到
    }
}
```

**volatile vs synchronized：**

| 特性     | volatile               | synchronized                   |
| -------- | ---------------------- | ------------------------------ |
| 可见性   | ✅                     | ✅                             |
| 原子性   | ❌（只能保证单次读写） | ✅                             |
| 有序性   | ✅（禁止指令重排）     | ✅                             |
| 性能     | 轻量                   | 较重                           |
| 适用场景 | 状态标志位、单次赋值   | 复合操作（++、check-then-act） |

## 7. 线程池

频繁创建销毁线程开销很大，线程池预先创建好一批线程，复用它们执行任务。

### 7.1 为什么用线程池

```
不用线程池：
  来一个任务 → 创建线程 → 执行任务 → 销毁线程
  开销大，线程数不可控，可能耗尽系统资源

用线程池：
  启动时创建 N 个线程 → 任务来了从池中取一个 → 执行完放回池中
  复用线程，控制并发数，避免资源耗尽
```

### 7.2 创建线程池

```java
import java.util.concurrent.*;

// 方式一：Executors 工厂方法（快速创建，生产环境不推荐）
ExecutorService pool1 = Executors.newFixedThreadPool(4);       // 固定 4 个线程
ExecutorService pool2 = Executors.newCachedThreadPool();       // 动态调整线程数
ExecutorService pool3 = Executors.newSingleThreadExecutor();   // 单线程
ScheduledExecutorService pool4 = Executors.newScheduledThreadPool(2); // 定时任务

// 方式二：ThreadPoolExecutor（推荐，参数透明可控）
ExecutorService pool = new ThreadPoolExecutor(
    2,                        // corePoolSize：核心线程数（常驻）
    4,                        // maximumPoolSize：最大线程数
    60L,                      // keepAliveTime：空闲线程存活时间
    TimeUnit.SECONDS,         // 时间单位
    new LinkedBlockingQueue<>(100),  // 任务队列（容量 100）
    new ThreadFactory() {     // 线程工厂（可自定义线程名）
        private int count = 0;
        @Override
        public Thread newThread(Runnable r) {
            return new Thread(r, "worker-" + (++count));
        }
    },
    new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
);
```

### 7.3 线程池核心参数

```
任务提交流程：

1. 当前线程数 < corePoolSize → 创建新线程执行
2. 当前线程数 >= corePoolSize → 任务放入队列
3. 队列满了，当前线程数 < maximumPoolSize → 创建临时线程
4. 队列满了，线程数也到上限 → 执行拒绝策略

拒绝策略（RejectedExecutionHandler）：
  AbortPolicy（默认）：抛出 RejectedExecutionException
  CallerRunsPolicy：由提交任务的线程自己执行
  DiscardPolicy：静默丢弃任务
  DiscardOldestPolicy：丢弃队列中最老的任务，重试提交
```

### 7.4 提交任务

```java
ExecutorService pool = Executors.newFixedThreadPool(3);

// execute：提交 Runnable，无返回值
pool.execute(() -> System.out.println("任务A，线程：" + Thread.currentThread().getName()));

// submit：提交 Callable，返回 Future
Future<String> future = pool.submit(() -> {
    Thread.sleep(1000);
    return "任务B的结果";
});

// 获取结果（阻塞直到完成）
String result = future.get();
System.out.println(result);  // 任务B的结果

// 检查是否完成（不阻塞）
boolean done = future.isDone();

// 取消任务
future.cancel(true);  // true = 中断正在运行的任务
```

### 7.5 关闭线程池

```java
// shutdown：不再接收新任务，等待已提交的任务执行完
pool.shutdown();

// shutdownNow：尝试中断正在运行的任务，返回未执行的任务列表
List<Runnable> unfinished = pool.shutdownNow();

// 等待所有任务完成（在 shutdown 后调用）
boolean terminated = pool.awaitTermination(10, TimeUnit.SECONDS);
```

### 7.6 定时任务

```java
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(2);

// 延迟执行（3秒后执行一次）
scheduler.schedule(
    () -> System.out.println("延迟执行"),
    3, TimeUnit.SECONDS
);

// 固定频率执行（1秒后开始，每2秒执行一次）
scheduler.scheduleAtFixedRate(
    () -> System.out.println("定时执行：" + LocalTime.now()),
    1, 2, TimeUnit.SECONDS
);

// 固定延迟执行（上次执行完毕后等2秒再执行下一次）
scheduler.scheduleWithFixedDelay(
    () -> System.out.println("固定延迟执行"),
    1, 2, TimeUnit.SECONDS
);
```

## 8. 常用并发工具类

### 8.1 AtomicInteger（原子操作）

不用 synchronized 也能保证原子性，基于 CAS（Compare-And-Swap）：

```java
import java.util.concurrent.atomic.AtomicInteger;

AtomicInteger counter = new AtomicInteger(0);

Runnable task = () -> {
    for (int i = 0; i < 1000; i++) {
        counter.incrementAndGet();  // 原子自增
    }
};

Thread t1 = new Thread(task);
Thread t2 = new Thread(task);
t1.start(); t2.start();
t1.join(); t2.join();

System.out.println(counter.get());  // 稳定是 2000

// 其他原子操作
counter.getAndIncrement();  // 先获取再自增（i++）
counter.incrementAndGet();  // 先自增再获取（++i）
counter.addAndGet(5);       // 加 5 并返回结果
counter.compareAndSet(10, 20);  // CAS：当前值是 10 时才更新为 20
```

### 8.2 ConcurrentHashMap

线程安全的 HashMap，比 HashTable 性能好得多：

```java
import java.util.concurrent.ConcurrentHashMap;

Map<String, Integer> map = new ConcurrentHashMap<>();

// 线程安全地统计词频
Runnable task = () -> {
    String[] words = {"apple", "banana", "apple", "cherry"};
    for (String word : words) {
        map.merge(word, 1, Integer::sum);  // 线程安全的计数
    }
};

Thread t1 = new Thread(task);
Thread t2 = new Thread(task);
t1.start(); t2.start();
t1.join(); t2.join();
System.out.println(map);
```

### 8.3 CountDownLatch（倒计时门闩）

等待多个线程都完成后再继续：

```java
import java.util.concurrent.CountDownLatch;

int threadCount = 5;
CountDownLatch latch = new CountDownLatch(threadCount);

for (int i = 0; i < threadCount; i++) {
    int taskId = i;
    new Thread(() -> {
        try {
            System.out.println("子任务 " + taskId + " 开始");
            Thread.sleep((long)(Math.random() * 1000));
            System.out.println("子任务 " + taskId + " 完成");
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            latch.countDown();  // 计数减一
        }
    }).start();
}

latch.await();  // 主线程等待，直到计数为 0
System.out.println("所有子任务完成，开始汇总结果");
```

### 8.4 CompletableFuture（异步编排）

JDK 8 引入，支持链式异步操作，是 Future 的增强版：

```java
import java.util.concurrent.CompletableFuture;

// 异步执行任务
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    // 模拟耗时操作（如调用外部 API）
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
    return "用户数据";
});

// 链式处理结果（类似 Promise 链）
future
    .thenApply(data -> data + " + 处理后")     // 转换结果
    .thenAccept(result -> System.out.println("最终结果：" + result))
    .exceptionally(e -> {
        System.out.println("出错：" + e.getMessage());
        return null;
    });

// 等待完成
future.join();

// 多个异步任务并行，等全部完成
CompletableFuture<String> f1 = CompletableFuture.supplyAsync(() -> "结果1");
CompletableFuture<String> f2 = CompletableFuture.supplyAsync(() -> "结果2");
CompletableFuture<String> f3 = CompletableFuture.supplyAsync(() -> "结果3");

CompletableFuture.allOf(f1, f2, f3).join();  // 等全部完成
String combined = f1.get() + ", " + f2.get() + ", " + f3.get();
System.out.println(combined);  // 结果1, 结果2, 结果3
```

## 9. 和 JavaScript 的对比

这是 Java 和 JavaScript 差异最大的部分之一。

### 并发模型差异

```
JavaScript：单线程 + 事件循环
  - 只有一个线程执行代码
  - 用异步（回调/Promise/async-await）避免阻塞
  - I/O 操作交给底层，完成后通过事件回调通知

Java：多线程
  - 可以同时有多个线程真正并行执行
  - I/O 操作可以阻塞当前线程（同步 IO）
  - 通过线程池管理并发
```

```javascript
// JavaScript：Promise 链（非阻塞）
fetch("/api/user")
  .then((res) => res.json())
  .then((user) => console.log(user))
  .catch((err) => console.error(err));

// 等价的 async/await
async function getUser() {
  try {
    const res = await fetch("/api/user");
    const user = await res.json();
    console.log(user);
  } catch (err) {
    console.error(err);
  }
}
```

```java
// Java：CompletableFuture（类似 Promise）
CompletableFuture.supplyAsync(() -> httpClient.get("/api/user"))
    .thenApply(res -> parseJson(res))
    .thenAccept(user -> System.out.println(user))
    .exceptionally(err -> {
        System.err.println(err.getMessage());
        return null;
    });

// 或者：直接同步调用（阻塞当前线程，在线程池中没问题）
try {
    String res = httpClient.get("/api/user");  // 阻塞直到完成
    User user = parseJson(res);
    System.out.println(user);
} catch (Exception e) {
    e.printStackTrace();
}
```

### 线程安全 vs JS 单线程天然安全

```javascript
// JS：单线程，不存在竞态条件
let count = 0;
for (let i = 0; i < 1000; i++) count++;
for (let i = 0; i < 1000; i++) count++;
console.log(count); // 永远是 2000，没有线程安全问题
```

```java
// Java：多线程，必须考虑线程安全
int count = 0;  // 危险！多线程操作会丢失更新

// 安全方案：
AtomicInteger safeCount = new AtomicInteger(0);
// 或者 synchronized 方法/块
```

**JDK 21 的虚拟线程（预览）：**

## 常见问题

**Q：`sleep()` 和 `wait()` 有什么区别？**  
A：`Thread.sleep()` 让当前线程休眠指定时间，**不释放锁**，时间到自动唤醒。`Object.wait()` 让当前线程等待，**释放锁**，需要其他线程调用 `notify()`/`notifyAll()` 唤醒，必须在 `synchronized` 块内使用。

**Q：线程池的线程数设置多少合适？**  
A：经验公式：

- **CPU 密集型任务**（大量计算）：核心数 + 1
- **IO 密集型任务**（大量等待）：核心数 × 2，或者根据等待时间/计算时间比值调整

实际生产中需要压测来确定最优值。

**Q：为什么阿里巴巴 Java 开发手册禁止用 `Executors` 创建线程池？**  
A：`Executors.newFixedThreadPool` 使用无界队列（`LinkedBlockingQueue`），任务可以无限堆积，可能导致 OOM（内存溢出）。`newCachedThreadPool` 最大线程数是 `Integer.MAX_VALUE`，可能创建大量线程耗尽系统资源。推荐手动创建 `ThreadPoolExecutor` 并明确所有参数。

**Q：`synchronized` 和 `ReentrantLock` 怎么选？**  
A：简单场景用 `synchronized`（JVM 自动加解锁，不会忘记释放）。需要以下功能时用 `ReentrantLock`：超时获取锁（`tryLock`）、可中断的锁等待、公平锁、多个条件变量。阶段六进阶篇会详细讲。

**Q：什么是 CAS，AtomicInteger 为什么不需要锁？**  
A：CAS（Compare-And-Swap）是 CPU 级别的原子指令：当内存中的值等于期望值时，才将其更新为新值，否则重试。这个过程是硬件保证原子的，不需要操作系统层面的锁。但 CAS 在高竞争下会频繁重试（自旋），这时反而不如锁效率高。
