## 1. 什么是 IoC

**IoC（Inversion of Control，控制反转）** 是一种设计思想，核心是把对象的创建和管理权从代码里"反转"给框架。

### 没有 IoC 的问题

```java
// 传统写法：对象自己创建依赖，强耦合
public class ArticleController {
    // 直接 new，Controller 和 Service 强绑定
    private ArticleService articleService = new ArticleServiceImpl();
    // ArticleService 和 ArticleRepository 强绑定
    // 想换实现？到处改代码
}

public class ArticleServiceImpl implements ArticleService {
    private ArticleRepository articleRepository = new ArticleRepositoryImpl();
    // 想测试 Service 但不想连真实数据库？没法 Mock
}
```

**问题：**

- 类与类之间强耦合，难以替换实现
- 难以单独测试（无法注入 Mock 对象）
- 对象生命周期完全由代码控制，无法复用单例

### 有了 IoC

```java
// IoC 写法：只声明需要什么，不管怎么创建
@RestController
public class ArticleController {
    private final ArticleService articleService;  // 只依赖接口

    // Spring 容器自动注入实现类
    public ArticleController(ArticleService articleService) {
        this.articleService = articleService;
    }
}

@Service
public class ArticleServiceImpl implements ArticleService {
    private final ArticleRepository articleRepository;

    public ArticleServiceImpl(ArticleRepository articleRepository) {
        this.articleRepository = articleRepository;
    }
}
```

**对象的创建和组装由 Spring 容器负责**，代码只声明"我需要什么"，不关心"怎么得到"。

## 2. 什么是依赖注入

**DI（Dependency Injection，依赖注入）** 是 IoC 的具体实现方式——容器在创建对象时，把其所需的依赖"注入"进去。

```
没有 DI：A 自己 new B（A 控制 B 的创建）
有了 DI：容器创建 B，再把 B 注入给 A（容器控制一切）

IoC 容器的职责：
1. 扫描并注册所有 Bean
2. 分析 Bean 之间的依赖关系
3. 按依赖顺序创建 Bean
4. 把依赖注入到对应的 Bean 中
5. 管理 Bean 的整个生命周期
```

## 3. Bean 的定义与注册

### 3.1 什么是 Bean

被 Spring IoC 容器管理的对象叫 **Bean**。Spring 容器负责创建、初始化、注入和销毁这些对象。

### 3.2 注解方式注册 Bean（主流）

```java
// @Component：通用组件，是其他注解的元注解
@Component
public class EmailSender {
    public void send(String to, String content) {
        System.out.println("发送邮件给 " + to + "：" + content);
    }
}

// @Service：业务层组件（语义上标识是 Service）
@Service
public class UserService {
    // ...
}

// @Repository：数据访问层组件
@Repository
public class UserRepository {
    // ...
}

// @Controller / @RestController：Web 控制器
@RestController
public class UserController {
    // ...
}
```

**四个注解的关系：**

```
@Component（基础）
    ↑
@Service      ← 语义：业务逻辑层
@Repository   ← 语义：数据访问层（额外支持异常转换）
@Controller   ← 语义：Web 控制器
```

功能上 `@Service`、`@Repository`、`@Controller` 都是 `@Component` 的特化版本，加了语义标识。

### 3.3 组件扫描

`@SpringBootApplication` 内含 `@ComponentScan`，默认扫描**启动类所在包及其所有子包**：

```
com.example.blogapi                    ← 启动类所在包（根包）
├── BlogApiApplication.java            ← @SpringBootApplication
├── controller/
│   └── ArticleController.java         ← ✅ 被扫描到
├── service/
│   └── ArticleService.java            ← ✅ 被扫描到
└── repository/
    └── ArticleRepository.java         ← ✅ 被扫描到

com.other.package/
└── SomeClass.java                     ← ❌ 不在根包下，不会被扫描
```

### 3.4 Bean 的命名

默认 Bean 名称是**类名首字母小写**：

```java
@Service
public class ArticleService { }
// Bean 名称：articleService

@Component("myEmailSender")  // 可以自定义名称
public class EmailSender { }
// Bean 名称：myEmailSender
```

## 4. 依赖注入的三种方式

### 4.1 构造器注入（推荐 ⭐）

```java
@Service
public class ArticleService {

    private final ArticleRepository articleRepository;
    private final UserService userService;

    // 只有一个构造器时，@Autowired 可以省略（Spring 4.3+）
    public ArticleService(ArticleRepository articleRepository,
                          UserService userService) {
        this.articleRepository = articleRepository;
        this.userService = userService;
    }
}
```

**优点：**

- 依赖不可变（`final`），对象创建后依赖不会被替换
- 依赖显式可见，一看构造器就知道需要什么
- 方便单元测试（直接 `new Service(mockRepo)` 注入 Mock）
- 可以发现循环依赖（启动时就报错，而不是运行时才崩）

### 4.2 字段注入（不推荐）

```java
@Service
public class ArticleService {

    @Autowired
    private ArticleRepository articleRepository;  // 直接注入字段

    @Autowired
    private UserService userService;
}
```

**缺点：**

- 依赖隐式，看不出需要什么
- 字段不能是 `final`，依赖可能被替换
- 测试时必须用反射注入（或 Spring 容器）
- IDEA 会警告：`Field injection is not recommended`

### 4.3 Setter 注入（可选依赖时使用）

```java
@Service
public class ArticleService {

    private ArticleRepository articleRepository;
    private EmailSender emailSender;  // 可选依赖

    @Autowired
    public void setArticleRepository(ArticleRepository articleRepository) {
        this.articleRepository = articleRepository;
    }

    @Autowired(required = false)  // 可选：Bean 不存在时不报错
    public void setEmailSender(EmailSender emailSender) {
        this.emailSender = emailSender;
    }
}
```

**适用场景：** 依赖是可选的（Bean 不存在时有默认行为），或需要在运行时动态更换依赖。

### 4.4 @Autowired vs @Resource

```java
// @Autowired（Spring 注解）：按类型注入
@Autowired
private UserService userService;

// @Resource（JDK 注解）：先按名称，再按类型
@Resource(name = "userServiceImpl")
private UserService userService;
```

**当同一接口有多个实现时：**

```java
public interface MessageSender {
    void send(String message);
}

@Component("emailSender")
public class EmailSender implements MessageSender { ... }

@Component("smsSender")
public class SmsSender implements MessageSender { ... }

// ❌ 报错：有两个 MessageSender 的实现，Spring 不知道注入哪个
@Autowired
private MessageSender messageSender;

// ✅ 方案一：用 @Qualifier 指定 Bean 名称
@Autowired
@Qualifier("emailSender")
private MessageSender messageSender;

// ✅ 方案二：变量名与 Bean 名称一致（按名称匹配）
@Autowired
private MessageSender emailSender;  // 名字匹配 emailSender

// ✅ 方案三：用 @Primary 标记默认实现
@Primary
@Component("emailSender")
public class EmailSender implements MessageSender { ... }
```

## 5. Bean 的作用域

```java
@Component
@Scope("singleton")   // 默认，整个容器只有一个实例
public class UserService { }

@Component
@Scope("prototype")   // 每次注入/获取都创建新实例
public class ShoppingCart { }

// Web 应用特有作用域
@Component
@Scope("request")     // 每个 HTTP 请求一个实例
public class RequestContext { }

@Component
@Scope("session")     // 每个 HTTP Session 一个实例
public class UserSession { }
```

**常用的就两种：**

| 作用域              | 说明                         | 适用场景                    |
| ------------------- | ---------------------------- | --------------------------- |
| `singleton`（默认） | 容器中只有一个实例，全部共享 | Service、Repository、工具类 |
| `prototype`         | 每次获取都创建新对象         | 有状态的对象（如购物车）    |

> ⚠️ **单例 Bean 注入多例 Bean 的问题：**  
> 单例的 Service 注入多例的 Bean，Spring 只注入一次，多例效果失效。需要通过 `ApplicationContext.getBean()` 或 `@Lookup` 每次手动获取。

## 6. Bean 的生命周期

```
1. 实例化    → 调用构造方法，创建对象
2. 属性赋值  → 依赖注入（@Autowired 等）
3. 初始化    → 执行 @PostConstruct 方法
4. 使用中    → Bean 正常工作
5. 销毁      → 执行 @PreDestroy 方法（容器关闭时）
```

```java
@Service
public class CacheService {

    private Map<String, Object> cache;

    // 构造方法执行后、属性注入完成后调用
    @PostConstruct
    public void init() {
        cache = new HashMap<>();
        System.out.println("CacheService 初始化，预热缓存...");
        // 可以在这里做初始化操作，如预加载数据、建立连接等
    }

    // 容器关闭时调用，做清理工作
    @PreDestroy
    public void destroy() {
        cache.clear();
        System.out.println("CacheService 销毁，清理缓存...");
    }

    public void put(String key, Object value) {
        cache.put(key, value);
    }

    public Object get(String key) {
        return cache.get(key);
    }
}
```

## 7. 条件装配

Spring Boot 大量使用条件注解来决定是否创建某个 Bean：

```java
// @ConditionalOnProperty：根据配置决定是否创建
@Bean
@ConditionalOnProperty(name = "app.email.enabled", havingValue = "true")
public EmailSender emailSender() {
    return new EmailSender();
}

// @ConditionalOnMissingBean：当容器中没有该类型 Bean 时才创建（提供默认实现）
@Bean
@ConditionalOnMissingBean(MessageSender.class)
public MessageSender defaultMessageSender() {
    return message -> System.out.println("默认发送：" + message);
}

// @ConditionalOnClass：classpath 中存在某个类时才创建
@Bean
@ConditionalOnClass(name = "com.mysql.cj.jdbc.Driver")
public DataSource dataSource() {
    // ...
}
```

这就是 Spring Boot 自动装配的核心——通过条件注解，只在满足条件时才创建 Bean，实现了"约定大于配置"。

## 8. 配置类与 @Bean

除了注解扫描，还可以用 Java 配置类手动定义 Bean（常用于第三方类或需要复杂初始化的 Bean）：

```java
@Configuration  // 标记这是配置类
public class AppConfig {

    // @Bean 方法的返回值注册为容器中的 Bean
    @Bean
    public RestTemplate restTemplate() {
        RestTemplate template = new RestTemplate();
        // 自定义配置...
        return template;
    }

    @Bean
    public ObjectMapper objectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.setDateFormat(new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"));
        mapper.setTimeZone(TimeZone.getTimeZone("Asia/Shanghai"));
        return mapper;
    }

    // @Bean 方法可以接收参数（Spring 自动注入）
    @Bean
    public ArticleService articleService(ArticleRepository articleRepository) {
        return new ArticleServiceImpl(articleRepository);
    }
}
```

**`@Component` vs `@Bean`：**

| 方式                        | 适用场景                                   |
| --------------------------- | ------------------------------------------ |
| `@Component` 等             | 自己写的类，可以加注解                     |
| `@Bean` in `@Configuration` | 第三方库的类，无法加注解；或需要复杂初始化 |

## 9. 和 JavaScript 框架的对比

### 和 NestJS 的对比（最相似）

```typescript
// NestJS（IoC 概念和 Spring 几乎一样）
@Injectable()
export class ArticleService {
  constructor(
    private readonly articleRepository: ArticleRepository,
    private readonly userService: UserService,
  ) {}
}

@Controller("articles")
export class ArticleController {
  constructor(private readonly articleService: ArticleService) {}
}

// 在 Module 中注册
@Module({
  controllers: [ArticleController],
  providers: [ArticleService, ArticleRepository],
})
export class ArticleModule {}
```

```java
// Spring Boot（比 NestJS 更自动化，不需要手动注册模块）
@Service
public class ArticleService {
    public ArticleService(ArticleRepository articleRepository,
                          UserService userService) { ... }
}

@RestController
public class ArticleController {
    public ArticleController(ArticleService articleService) { ... }
}
// 只需要 @Service / @RestController 注解，容器自动扫描和注册
// 不需要 NestJS 那样手动写 Module
```

### 和 Vue 依赖注入的对比

```typescript
// Vue 3 provide/inject（简单版 IoC）
// 父组件 provide
provide("userService", userService);

// 子组件 inject
const userService = inject("userService");
```

Vue 的 provide/inject 是组件树级别的，Spring 的 IoC 容器是应用级别的，管理的对象多得多。

## 练习

### 练习 1：理解 Bean 注册

在 Spring Boot 项目中：

1. 创建 `service/GreetingService.java`（用 `@Service`），提供 `greet(String name)` 方法返回问候语
2. 创建 `service/TimeService.java`（用 `@Component`），提供 `getCurrentTime()` 返回当前时间字符串
3. 在 `controller/DemoController.java` 中用**构造器注入**这两个 Service
4. 提供接口 `GET /demo/greet?name=张三`，同时调用两个 Service，返回组合结果

### 练习 2：多实现注入

1. 定义接口 `StorageService`，有 `upload(String filename)` 和 `delete(String filename)` 方法
2. 实现两个类：`LocalStorageService`（用 `@Component("localStorage")`）和 `OssStorageService`（用 `@Component("ossStorage")`）
3. 在 `FileController` 中用 `@Qualifier` 注入 `localStorage`
4. 用 `@Primary` 把 `OssStorageService` 标为默认，再去掉 `@Qualifier`，观察注入的是哪个

### 练习 3：Bean 生命周期

1. 创建 `DataCacheService`，在 `@PostConstruct` 里预加载 10 条模拟数据（存入 Map）
2. 在 `@PreDestroy` 里打印"缓存清理完毕"
3. 提供查询接口 `GET /cache/{key}`，返回缓存中的数据
4. 启动应用观察 `@PostConstruct` 的执行时机，关闭应用（Ctrl+C）观察 `@PreDestroy`

### 练习 4（进阶）：手写简易 IoC

不用 Spring，用纯 Java 实现一个极简 IoC 容器：

```java
public class SimpleContainer {
    private Map<Class<?>, Object> beans = new HashMap<>();

    // 注册 Bean
    public <T> void register(Class<T> type, T instance) { ... }

    // 获取 Bean
    public <T> T getBean(Class<T> type) { ... }

    // 通过反射自动注入（扫描字段上的 @Autowired）
    public void inject(Object target) { ... }
}
```

实现后，用它管理 `UserService`（依赖 `UserRepository`），验证注入功能正常。

## 常见问题

**Q：`@Autowired` 和构造器注入哪个更好？**  
A：官方和业界一致推荐**构造器注入**，Spring 官方文档、IDEA 的代码检查都会提示字段注入不推荐。主要原因：字段注入隐藏了依赖关系，不利于测试，也无法保证依赖不可变。构造器注入的代码稍微多一些，但可以配合 Lombok 的 `@RequiredArgsConstructor` 自动生成（下一节会介绍）。

**Q：循环依赖是什么，Spring 如何处理？**  
A：A 依赖 B，B 依赖 A，叫循环依赖。Spring 对单例 Bean 的字段注入/Setter 注入有循环依赖的解决机制（三级缓存），但**构造器注入的循环依赖会直接启动报错**（这反而是好事，强制你重新设计）。遇到循环依赖一般说明设计有问题，应该拆分职责或引入中间层。

**Q：`@Component` 扫描的范围怎么修改？**  
A：在启动类上用 `@ComponentScan` 指定：

```java
@SpringBootApplication
@ComponentScan(basePackages = {"com.example", "com.other"})
public class Application { }
```

**Q：Spring 容器和 Bean 是单例的，多线程访问会有问题吗？**  
A：Bean 默认单例，但单例本身不代表线程安全。如果 Bean 有可变的**成员变量**，多线程并发修改就会有问题。Spring 的 Service、Repository 等通常设计为**无状态的**（不保存请求相关的数据在字段里），这样单例就是线程安全的。如果需要保存状态，应该放在方法的局部变量里，或用 `prototype` 作用域。
