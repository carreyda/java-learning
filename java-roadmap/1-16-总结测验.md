## 2. 核心概念速查

### Java 基础

```java

// Integer 缓存：-128 ~ 127 用 ==，其他用 equals()

// String 不可变，比较用 equals()

String s2 = new String("hello");
s1 == s2      // false（不同对象）
s1.equals(s2) // true（内容相同）

// 整数除法截断
10 / 3   // 3（不是 3.33）
(double) 10 / 3  // 3.333...
```

### 面向对象

```java
// 三大特性
封装：private 属性 + public getter/setter
继承：extends（单继承），子类拥有父类非 private 成员
多态：父类引用指向子类对象，运行时动态绑定

// 关键字
this：当前对象引用
super：父类引用
static：属于类，不属于对象
final：类（不可继承）、方法（不可重写）、变量（常量）

// 接口 vs 抽象类
接口：can-do 关系，可多实现，无构造方法，字段默认 public static final
抽象类：is-a 关系，单继承，可有构造方法，可有普通方法和字段

// 重写 vs 重载
重写(Override)：子类 + 父类，方法签名相同，运行时多态
重载(Overload)：同一类，方法名相同，参数列表不同，编译时确定
```

### 集合框架

```java
// 选型
需要有序可重复    → ArrayList（随机访问 O(1)）
需要去重         → HashSet（无序）/ LinkedHashSet（保序）/ TreeSet（排序）
需要键值对       → HashMap（无序）/ LinkedHashMap（保序）/ TreeMap（排序）
频繁头部增删     → LinkedList

// HashMap 底层（JDK 8+）
数组 + 链表 + 红黑树
初始容量 16，负载因子 0.75，扩容阈值 12
链表长度 >= 8 且数组长度 >= 64 时转红黑树
容量始终是 2 的幂（下标计算用位运算替代取模）

// Comparable vs Comparator
Comparable：类内部实现（compareTo），自然排序，改类本身
Comparator：外部传入，灵活定制多种排序，不改类
```

### 异常体系

```java
Throwable
  ├── Error（不处理：OOM、StackOverflow）
  └── Exception
        ├── RuntimeException（非受检，不强制处理：NPE、IOOBE）
        └── 其他（受检，必须处理：IOException、SQLException）

// 原则
只捕获能处理的具体异常
不要吞掉异常（至少打日志）
业务异常继承 RuntimeException
finally 不要 return（会吞掉异常）
资源释放用 try-with-resources
```

```java
// 三种创建方式
extends Thread      → 重写 run()

```

## 3. 面试高频问题

### 3.1 Java 基础

**Q：int 和 Integer 的区别？**

int 是基本类型，直接存储数值，占 4 字节，不能为 null。Integer 是包装类，是对象，存储在堆上，可以为 null。集合只能存对象所以要用 Integer。JDK 5+ 支持自动装拆箱，但注意 Integer 比较要用 `equals()`，因为 `==` 比较的是引用，且 `-128~127` 有缓存导致 `==` 结果不一致。

**Q：String、StringBuilder、StringBuffer 的区别？**

String 不可变，每次操作创建新对象，适合少量拼接。StringBuilder 可变，非线程安全，适合单线程大量拼接，性能最好。StringBuffer 可变，线程安全（方法加 synchronized），多线程拼接时使用，性能比 StringBuilder 略差。

**Q：== 和 equals() 的区别？**

`==` 比较基本类型时比较值，比较引用类型时比较内存地址（是否同一个对象）。`equals()` 默认也是比较地址（Object 的实现），但 String、Integer 等类重写了 `equals()` 改为比较内容。自定义类应该重写 `equals()` 和 `hashCode()`。

---

### 3.2 面向对象

**Q：接口和抽象类的区别？**

接口用 `interface` 定义，`implements` 实现，可以多实现，只能有 `public static final` 常量，JDK 8+ 可以有 `default` 和 `static` 方法，没有构造方法。抽象类用 `abstract class`，`extends` 继承，只能单继承，可以有任意访问修饰符的字段和方法，可以有构造方法。选择：is-a 关系用抽象类，can-do 关系用接口。

**Q：重写和重载的区别？**

重写（Override）发生在子类和父类之间，方法名、参数列表、返回值必须相同，运行时根据对象的实际类型动态决定调用哪个，是多态的体现。重载（Overload）发生在同一个类中，方法名相同但参数列表不同（个数或类型），编译时就确定调用哪个，与返回值和访问修饰符无关。

**Q：什么是多态？有什么用？**

多态是父类引用指向子类对象，调用方法时在运行时动态决定调用哪个实现。前提：继承/实现接口 + 方法重写。好处：统一接口处理不同类型的对象，对新增类型扩展友好，不需要修改已有代码（开闭原则）。

---

### 3.3 集合框架

**Q：ArrayList 和 LinkedList 的区别？**

底层结构：ArrayList 是动态数组，LinkedList 是双向链表。随机访问：ArrayList O(1)，LinkedList O(n)。插入删除：ArrayList 中间插删需要移动元素 O(n)，LinkedList 头尾 O(1) 中间也是 O(n)（还要先找到位置）。实际建议几乎总是用 ArrayList，RandomAccess 更适合大多数场景。

**Q：HashMap 的底层原理？**

JDK 8 后是数组 + 链表 + 红黑树。put 时计算 key 的 hash，通过 `hash & (capacity-1)` 得到数组下标，该位置为空则直接放，有元素则比较 key（先比 hash 再 equals），相同则覆盖，不同则加入链表尾部。链表长度达到 8 且数组长度达到 64 时链表转红黑树。元素数量超过 `capacity × loadFactor`（默认 12）时扩容为 2 倍。

**Q：HashMap 为什么容量是 2 的幂次方？**

计算下标时用 `hash & (n-1)` 代替 `hash % n`，位运算比取模快。n 为 2 的幂次时，`n-1` 的二进制全是 1（如 15 = 1111），与操作结果能均匀分布，减少哈希冲突。

**Q：ConcurrentHashMap 和 HashMap 的区别？**

HashMap 非线程安全，并发修改可能数据丢失。ConcurrentHashMap 线程安全，JDK 8 用 CAS + synchronized 锁住单个数组节点（比 JDK 7 的分段锁粒度更细），并发性能好，支持多线程同时读写不同节点。

---

### 3.4 Java 8 新特性

**Q：Lambda 表达式是什么？**

Lambda 是匿名函数，用于简化函数式接口的实现。语法：`(参数) -> 表达式` 或 `(参数) -> { 语句块 }`。本质是函数式接口的匿名实现，编译后生成一个对象。捕获的外部变量必须是 effectively final。

**Q：Stream 的 map 和 flatMap 的区别？**

`map` 是一对一转换，每个元素映射为一个新元素，结果元素数量不变。`flatMap` 是一对多，每个元素映射为一个 Stream，然后将所有 Stream 合并（展平）为一个 Stream，用于处理嵌套结构（如 `List<List<T>>` 展平为 `List<T>`）。

**Q：Optional 的作用是什么？**

Optional 是一个可能为空的容器，用来优雅地处理 null，避免大量 null 判断和 NPE。常见用法：方法返回 Optional 表示可能没有结果，调用方用 `orElse`/`orElseThrow`/`ifPresent` 处理。不应该用作方法参数和类字段。

---

### 3.5 多线程

**Q：线程的创建方式有哪些？**

三种：① 继承 Thread 类，重写 `run()` 方法；② 实现 Runnable 接口，实现 `run()` 方法，推荐，避免单继承限制；③ 实现 Callable 接口，实现 `call()` 方法，有返回值，配合 FutureTask 使用。实际开发中通常通过线程池提交任务，不直接创建线程。

**Q：synchronized 的作用和原理？**

保证同一时刻只有一个线程执行被修饰的方法或代码块，解决可见性、原子性、有序性问题。修饰实例方法时锁对象是 this，修饰静态方法时锁对象是 Class 对象，修饰代码块时锁指定的对象。底层基于对象头中的 Monitor（监视器锁），JVM 会在进入时执行 monitorenter，退出时执行 monitorexit。

**Q：volatile 的作用？和 synchronized 的区别？**

volatile 保证变量的可见性（修改后立即对其他线程可见）和有序性（禁止指令重排），但不保证原子性。适合状态标志位、单次赋值等场景。synchronized 同时保证可见性、原子性和有序性，但是重量级操作，性能较差。简单的单变量状态用 volatile，复合操作（如 `count++`）用 synchronized 或 AtomicXxx。

**Q：为什么不推荐用 Executors 创建线程池？**

`newFixedThreadPool` 和 `newSingleThreadExecutor` 使用无界的 `LinkedBlockingQueue`，任务可以无限堆积导致 OOM。`newCachedThreadPool` 最大线程数是 `Integer.MAX_VALUE`，可能创建大量线程耗尽系统资源。应该直接使用 `ThreadPoolExecutor`，明确指定队列容量和拒绝策略。

## 5. 常见坑点汇总

学完阶段一，以下是最容易出错的地方，进入阶段二前务必确认已理解：

```java
// ❌ 坑1：整数除法
int result = 10 / 3;  // 3，不是 3.33

// ❌ 坑2：字符串 == 比较
String a = new String("hello");
String b = new String("hello");
a == b  // false！应该用 equals()

// ❌ 坑3：Integer 超出缓存范围用 ==
Integer x = 128;
Integer y = 128;
x == y  // false！应该用 equals()

// ❌ 坑4：ArrayList 删除整数元素
List<Integer> list = new ArrayList<>(List.of(1, 2, 3));
list.remove(1);  // 删除下标1，不是值1！
list.remove(Integer.valueOf(1));  // 才是删除值1

// ❌ 坑5：增强for循环中删除元素
for (String s : list) {
    list.remove(s);  // ConcurrentModificationException！
}
list.removeIf(s -> ...);  // 正确做法

// ❌ 坑6：HashMap 在多线程下使用
// 应该用 ConcurrentHashMap

// ❌ 坑7：String.length() 是方法不是属性
s.length   // ❌ 编译报错
s.length() // ✅

// ❌ 坑8：直接打印数组
int[] arr = {1, 2, 3};
System.out.println(arr);              // [I@1b6d3586（内存地址）
System.out.println(Arrays.toString(arr));  // [1, 2, 3]

// ❌ 坑9：finally 中 return
public int test() {
    try { return 1; }
    finally { return 2; }  // 返回 2，并吞掉 try 中的 return
}

// ❌ 坑10：Stream 重复消费
Stream<String> stream = list.stream();
stream.forEach(...);
stream.count();  // IllegalStateException！Stream 已被消费

// ❌ 坑11：直接调用 run() 而不是 start()
Thread t = new Thread(() -> { ... });
t.run();    // 在当前线程同步执行，不创建新线程
t.start();  // 才是启动新线程

// ❌ 坑12：线程 sleep 忘处理 InterruptedException
Thread.sleep(1000);  // 编译报错，必须 try-catch
try { Thread.sleep(1000); } catch (InterruptedException e) {
    Thread.currentThread().interrupt();  // 记得恢复中断标志
}
```

### 需要提前了解的概念

以下概念在阶段二会频繁用到，可以提前了解：

**Maven：** Java 的包管理工具，类似 Node.js 的 npm。通过 `pom.xml` 声明依赖，Maven 自动下载和管理 jar 包。

**注解驱动开发：** Spring Boot 大量使用注解（`@Component`、`@Autowired`、`@RequestMapping`），本质是利用反射在运行时读取注解并做相应处理，1-12 的反射和注解知识是理解 Spring 的关键。

**依赖注入（DI）：** 对象不自己创建依赖，而是由框架注入。就像 `Repository` 接口和实现的分离——上层只依赖接口，不依赖具体实现，具体实现由外部注入。

**MVC 模式：** Model（数据）- View（展示）- Controller（控制器），Web 开发的经典分层模式。Spring Boot 的 REST API 开发就是 MVC 的实践。
